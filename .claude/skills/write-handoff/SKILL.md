# 인수인계 작성

## 언제 발동하나

- 사용자가 인수인계를 요청한다. 예: "인수인계 남겨줘", "핸드오버 문서 써줘", "여기까지 정리해줘", "다음 세션이 이어받게 해줘".
- 사용자가 작업을 중단·종료하겠다고 밝혔는데 남은 일이 있다. 예: "오늘은 여기까지", "이건 나중에 하자".
- 3인 접속 테스트, 다른 파트 인터페이스 확정, 디자인 결정 등을 기다리며 작업이 멈췄다.

작업이 완전히 끝났고 커밋까지 마쳤으며 남은 위험도 없으면 인수인계를 새로 만들지 않는다. 대신 `HANDOFF_CURRENT.md` 표에서 해당 항목을 지운다.

## 절차

### 1. 기존 항목인지 먼저 확인한다

- `.claude/docs/HANDOFF_CURRENT.md`를 읽고, 지금 작업이 표에 이미 있는지 본다.
- **있으면 새 문서를 만들지 않는다.** 표가 가리키는 원본 문서를 열어 그 문서를 갱신한다. 날짜 폴더도 옮기지 않는다 — 옮기면 이전 세션이 남긴 경로가 끊긴다.
- 없으면 새 문서를 만든다. 경로는 `.claude/docs/{오늘 날짜}/{kebab-case 작업명}.md`.
- 이어받은 작업인지 애매하면 임의로 판단하지 말고 사용자에게 어느 항목인지 확인한다.

### 2. 사실을 수집한다 — 기억으로 쓰지 않는다

문서에 적을 값은 전부 확인하고 쓴다.

- `git status`, `git log --oneline -5`, `git branch --show-current` — 커밋한 것 / 커밋하지 않은 변경 / 브랜치.
- 이번 세션에 수정한 씬 이름, 신규·수정한 ScriptableObject 경로, 신규 프리팹·에셋 경로.
- 실제로 돌린 검증과 그 결과. 관찰하지 않은 것은 관찰했다고 쓰지 않는다.
- 확인할 수 없는 값(예: 인스펙터에서만 보이는 설정)은 값을 적지 말고 **재확인 방법**을 적는다.

### 3. 양식대로 쓴다

- 양식은 [세션 인수인계](../../../docs/ai/05_SESSION_HANDOFF.md)의 템플릿 8개 절을 그대로 쓴다. 절을 임의로 늘리거나 줄이지 않는다.
- 검증 상태 어휘는 [검증 플레이북](../../../docs/ai/03_VERIFICATION_PLAYBOOK.md)을 따른다. `완료(검증됨)` / `구현됨(미검증)`을 섞어 쓰지 않는다.
- 관찰한 사실과 추정을 문장 단위로 구분한다. 추정에는 추정이라고 적는다.
- 7절 "다음 세션의 첫 행동"은 명령형으로, 실행 순서대로 적는다. "확인 필요" 같은 모호한 문장 대신 무엇을 어떻게 확인하는지 적는다.
- 6절 차단 조건에는 **누가 무엇을 해줘야 풀리는지**를 적는다.

### 4. 이 프로젝트에서 빠뜨리면 안 되는 것

| 항목 | 왜 |
|---|---|
| 수정한 씬 이름 | 다음 세션이 다른 씬을 열면 작업이 보이지 않는다 |
| 신규 ScriptableObject 경로 | 인스펙터 값 입력이 있어야 동작하는 경우가 많다 |
| 멀티플레이 검증 등급(M0~M2) | 신뢰도를 결정한다. 네트워크 변경인데 3인 미검증이면 반드시 명시 |
| 다른 파트에 요청한 인터페이스 | 답을 못 받으면 계속 막힌다 |
| 테스트용으로 되돌려야 할 설정 | 예: Build Settings 시작 씬, `_devMinPlayers` 같은 임시 값 |

### 5. 문서 안의 상대 경로를 확인한다

- 날짜 폴더는 저장소 루트에서 3단계 아래다. 기준 문서 링크 접두사는 `../../../docs/`다.
- 이전 인수인계를 복사해 쓴 경우 특히 확인한다. 경로가 틀리면 조용히 깨진 채 남는다.

### 6. 포인터 표를 갱신한다

- `.claude/docs/HANDOFF_CURRENT.md`의 표에 항목 · 경로 · 상태를 갱신한다.
- **본문을 포인터에 복사하지 않는다.** 상태 칸에는 지금 어디까지 됐고 무엇이 막혔는지만 한두 줄로 적는다.
- 끝난 항목은 표에서만 지운다. 문서는 날짜 폴더에 남긴다.

### 7. 사용자에게 보고한다

- 쓴 문서 경로와, 포인터 표에서 무엇을 바꿨는지 알린다.
- 확인하지 못해 비워둔 칸이 있으면 무엇을 왜 못 채웠는지 명시한다.

## 하지 않는 것

- 확인하지 않은 값을 기억이나 추측으로 채우기
- 검증하지 않은 항목을 `완료(검증됨)`으로 적기
- 이미 있는 항목에 대해 오늘 날짜로 새 문서를 만들기 (원본을 갱신한다)
- `HANDOFF_CURRENT.md`에 본문 복사하기
- `.claude/docs/` 파일을 커밋하려 시도하기 — `.gitignore` 대상이다. 저장소에 남겨야 하는 결정은 `docs/`에 따로 쓴다
- 인수인계를 쓰는 김에 코드나 설정을 함께 고치기 — 이 스킬은 기록만 한다
