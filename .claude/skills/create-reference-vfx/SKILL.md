# 영상 참조 Unity VFX 제작

참조의 형태·움직임·타이밍을 게임에서 재생되는 효과로 재구성한다. 산출물은 조절 가능한 프리팹과 필요한 재질·셰이더·텍스처·메시, 재생 연결 및 비교 캡처다. 원본 내부 구현을 추측으로 단정하거나 근거 없는 유사도 백분율을 보고하지 않는다.

## 필수 품질 기준: 참조 캡처 대비 90% 이상

- **원본 영상과 동등한 시각적 품질, 참조 캡처 대비 90% 이상 유사도를 제작 목표이자 완료 기준으로 삼는다.** 사용자가 더 높은 목표(예: 99%)를 지정하면 그 수치를 이 작업의 목표로 올린다. 러프·프로토타입을 명시적으로 요청한 경우에만 낮춘다. 비슷한 색과 대략적인 궤적만 구현한 결과를 최종 완성품으로 제출하지 않는다.
- 참조의 주요 인상을 만드는 요소를 모두 제작 범위에 포함한다. 칼날의 면적·두께·날카로운 끝·겹침, 불규칙한 텍스처, 어두운 연기, 파편, 불티의 밀도·분포, 지면 잔광과 후처리 중 실제 참조에 있는 요소를 확인한다. 구현이 번거롭다는 이유로 생략하거나 다음 작업으로 넘기고 완료로 처리하지 않는다.
- 절차적 메시만으로 목표 품질에 도달하지 못하면 필요한 텍스처·플립북·셰이더·Meshy 모델·후처리까지 제작 방식을 확장한다. 단순한 균일 곡선이나 발광 선으로 복잡한 칼날·연기를 대신한 결과는 중간 시안이다.
- **참조 캡처와 Unity 결과를 같은 동작 시점별로 나란히 놓고 Read 도구로 직접 보며 비교 → 차이가 큰 요소 수정 → 재캡처**를 반복한다. 사용자에게 비교 작업을 떠넘기거나 첫 시안을 만든 단계에서 종료하지 않는다. 기능 테스트 통과는 시각적 품질 통과를 대신하지 않는다.
- 타격마다 시작·최대 강도·확산·소멸 프레임을 비교하고 정상 속도 영상도 확인한다. 가장 잘 나온 한 프레임만 선택하지 않는다. 두 번의 공격이면 두 타격 모두 방향·간격·속도·잔상까지 일치시킨다.
- 카메라 각도, 화면 점유율, 해상도, 노출을 가능한 한 맞춘다. 배경·캐릭터·자막 차이가 효과 비교를 지배하지 않도록 VFX 영역을 중심으로 비교하되, 연기·파편 등 불일치를 숨기기 위해 영역을 잘라내지 않는다. 실제 게임 카메라에서의 가독성도 별도로 검증한다.
- 목표 수치는 달성했다고 자동으로 붙이는 값이 아니다. 수치 평가를 사용할 때는 비교 프레임·영역·정렬 방법·평가 항목·산정 방식·결과를 남긴다. 픽셀 유사도만으로 효과 품질을 판정하지 않으며 배경 때문에 높게 나온 점수로 통과시키지 않는다. 육안 평가는 **시각적 추정**으로 명시하고 객관적으로 측정된 값이라고 표현하지 않는다.
- 핵심 요소 누락이나 뚜렷한 형태·타이밍 차이가 있으면 점수와 관계없이 미달이다. 목표치를 뒷받침할 증거가 없으면 **품질 목표 미달 또는 달성 미검증**으로 보고한다. 권한·입력·서비스·예산 등 실제 제약으로 진행이 막힐 때만 결과와 구체적인 남은 차이를 보존해 알리고, 낮은 품질을 완성으로 포장하지 않는다.

## 작업 범위와 준비

- 이 스킬로 요청한 효과를 만드는 데 필요한 **모델링 파일은 Meshy AI를 활용하고, 포스트프로세싱도 필요하면 구현한다.** 필요성을 설명하고 진행하며 이미 허용된 작업을 단계마다 재승인받지 않는다.
- 이 허용은 해당 효과 제작 범위다. 새 유료 구독·크레딧 구매, 무제한 생성 반복, 무관한 프로젝트 전역 아트 변경이나 배포로 확대하지 않는다.
- 저장소 지침과 현재 변경을 확인한다. Unity 버전, 렌더 파이프라인, 사용 중인 VFX·풀링·카메라·Volume 구조를 실제 파일에서 확인한다. 특정 프로젝트의 설치 상태를 다른 세션에도 보장된 사실로 취급하지 않는다.
- 원본 파일 또는 접근 가능한 URL과 대상 시간 구간을 확보한다. 여러 효과 중 대상이 불명확할 때만 질문한다. 색·크기·수명은 문맥에서 초안을 정하고 조절 가능하게 만든다. 영상을 읽지 못했으면 분석했다고 하지 말고 로컬 파일이나 핵심 프레임을 요청한다.

## Unity 에디터를 조작하는 경로

Claude 세션에는 Unity MCP 도구가 기본으로 붙어 있지 않다. 착수 전에 아래 순서로 실제 가능한 경로를 확인하고, 안 되는 경로를 된다고 가정하지 않는다.

1. `ToolSearch`로 `mcp__*unity*` 도구가 이 세션에 로드돼 있는지 본다. 있으면 그대로 쓴다.
2. 없으면 **HTTP 브리지에 직접 붙는다.** `~/.claude.json`의 프로젝트 항목에서 UnityMCP URL(보통 `http://127.0.0.1:8080/mcp`)을 확인하고, `.claude/tools/umcp.py` 같은 헬퍼로 `initialize` → `notifications/initialized` → `tools/call`을 수행한다. 응답은 SSE(`data: ` 줄)다. `PYTHONIOENCODING=utf-8`을 설정하지 않으면 한글·기호 출력이 cp949에서 깨진다.
3. 브리지도 없고 에디터가 켜져 있으면 `-batchmode`는 프로젝트 잠금 때문에 실패한다. 이때만 사용자에게 에디터를 닫아 달라고 요청한다.

브리지에서 실제로 쓸 도구: `execute_code`(에디터 안에서 임의 C# 실행 — 프리팹 빌드·PlayMode 캡처·측정에 가장 강력), `manage_asset`, `manage_material`, `manage_shader`, `manage_prefabs`, `manage_graphics`(Volume·후처리), `manage_scene`, `run_tests`/`get_test_job`, `read_console`, `refresh_unity`, `generate_model`(Meshy), `generate_image`.

작업 전 `mcpforunity://editor/state`를 읽어 `data.advice.ready_for_tools`, 컴파일 여부, 현재 씬, PlayMode 상태를 확인한다. 스크립트를 고친 뒤에는 `refresh_unity` 후 `read_console`로 컴파일 오류부터 본다.

**에디터 상태를 함부로 바꾸지 않는다.** 다른 사람이 열어 둔 씬을 저장하거나, dirty 상태의 무관한 에셋을 `SaveAssets`로 한꺼번에 저장하지 않는다. 저장은 `AssetDatabase.SaveAssetIfDirty(대상)`으로 범위를 좁힌다. PlayMode를 켰으면 반드시 끄고, `Application.runInBackground` 같은 전역 설정을 임시로 바꿨으면 원래 값으로 되돌린다.

## 참조 분석과 제작

1. FFmpeg로 대상 구간의 프레임과 타임스탬프를 추출하고 **Read 도구로 직접 본다.** 프레임을 한 장씩 보지 말고 시각을 각 칸에 써 넣은 컨택트 시트로 묶어서 보면 타이밍을 한 번에 읽을 수 있다. 시작·최대 강도·확산·소멸 구간을 포함하고 빠른 변화 구간은 더 촘촘히 추출한다. 원본 FPS, 배속·슬로모션 여부를 확인해 영상 시간과 게임 재생 시간을 구분한다. 참조 파일과 분석 중간물은 Unity 임포트 폴더 밖에 둔다.
2. 눈으로만 보지 말고 프레임별 수치도 뽑는다. numpy/PIL로 효과 색 마스크의 픽셀 수·평균 밝기·중심·분포를 재면 타격 시작 프레임, 정점, 감쇠 곡선, 두 타격 간격을 추정으로 두지 않고 확정할 수 있다.
3. 섬광, 궤적, 입자, 연기, 지면 효과, 메시, 화면 후처리를 구분한다. 각 요소의 시작 시각·수명·크기·색·이동·투명도 변화를 기록한다. 피사체 발광과 카메라 노출 변화처럼 단일 영상에서 구별되지 않는 부분은 추정으로 표시한다.
4. 기존 효과와 에셋을 조사하고 Particle System, VFX Graph, Trail, 메시·셰이더를 효과 특성에 맞춰 조합한다. 기존 구현을 무조건 교체하거나 모든 효과에 VFX Graph를 강제하지 않는다. 새 3D 에셋이 필요하면 아래 Meshy 절차로 이어간다.
5. 먼저 실루엣과 발생·소멸 타이밍을 맞춘 뒤 색·입자·텍스처·발광을 조정한다. 비트맵이 필요하면 절차적 생성(코드로 텍스처를 만들어 PNG로 임포트)이나 `generate_image`를 쓴다. 생성한 한 장의 그림을 시간 일관성이 검증된 애니메이션 시트로 간주하지 않는다.
6. 크기, 색, 강도, 지속시간 등 조절값을 프로젝트의 기존 설정 방식에 노출한다. 무기 부착·월드 좌표·로컬 좌표, 풀 재사용, 취소·비활성화·일시정지·종료 처리를 확인한다. 반복 재생 때 이전 입자나 후처리가 남지 않도록 한다.

## 모델이 필요할 때: Meshy AI

- 단순 평면·링·리본은 기존 메시나 절차적 기하로 처리할 수 있다. 별도 조형이 필요한 파편·소환체·장식 등 신규 모델링 에셋은 Meshy AI로 제작한다. 다른 생성 서비스로 임의 대체하지 않는다.
- `generate_model` 도구의 현재 스키마와 제공자 목록으로 Meshy 설정을 확인한다. 도구 이름만 보고 인증·크레딧·정상 작동을 단정하지 않는다.
- VFX 레이어에 필요한 형태만 생성한다. 프롬프트에 실루엣, 피벗·축 의도, 실제 크기, 재질 분리, 목표 복잡도를 명시하되 결과가 이를 지켰는지 별도 검사한다. 변형 애니메이션이 필요하지 않은 모델에 리깅을 추가하지 않는다.
- 기존 생성 권한과 예산 내에서 최소 후보를 생성한다. 제출 후 작업 ID를 저장하고 상태를 조회하며, 타임아웃을 새 생성 요청으로 대체하지 않는다. 실패 시 원인을 고쳐 제한적으로 재시도한다. 품질 개선 재생성은 관찰한 결함과 개선안을 정한 뒤 수행하고 예산 한도 또는 같은 실패가 반복되면 멈춘다.
- 인증이나 잔액이 없으면 비밀값을 출력하거나 채팅으로 키를 요구하지 않는다. 필요한 설정을 알리고 임시 메시로 나머지 작업을 진행하되 Meshy 완료로 보고하지 않는다.
- 다운로드 후 실제 지원되는 FBX/GLB 등의 임포트 경로를 확인한다. 텍스처 동반 파일, 스케일·피벗·노멀·UV·삼각형 수·재질 수와 URP 등 현재 파이프라인의 재질 변환을 검수한다. 불필요한 충돌체는 넣지 않는다.
- 게임 카메라에서 검수하고 필요하면 리메시하거나 가공한다. 프롬프트·작업 ID·최종 파일·가공 내역과 프로젝트 관례에 맞는 출처 기록을 남긴다.

## 필요한 포스트프로세싱

- 참조 재현에 기여하는 경우 Bloom, 색·노출 변화, 비네트, 화면 왜곡 등을 구현한다. 물체 표면의 디졸브·왜곡과 화면 전체 후처리를 구분해 적절한 위치에 구현한다. 카메라 흔들림은 별도 카메라 연출로 구분하고 요청 범위에 포함될 때 연결한다.
- 기존 Volume, 프로필 공유 관계, 우선순위, 카메라 스택·레이어 마스크와 후처리 활성화 상태부터 확인한다. 해당 Unity/URP 버전의 렌더 기능·API를 검증한다.
- 효과 전용 프로필이나 기존 후처리 제어기에 연결해 영향 범위를 드러낸다. 공용 프로필을 수정해야 하면 영향받는 카메라·씬을 먼저 확인하고 알린다. 필요 이상으로 프로젝트 전체 렌더 설정을 변경하지 않는다.
- 시작·최대 강도·복귀 곡선과 중첩 규칙을 구현한다. 종료·취소·사망·비활성화·씬 전환 때 자신이 소유한 기여분을 해제하고 기존 화면 상태로 복귀시킨다. 중첩 효과 종료 시 다른 활성 효과의 값을 덮어쓰지 않는다.
- 게임 카메라에서 발광 번짐, 배경·적·공격 예고·UI 가독성을 확인한다. 후처리 켬/끔 비교로 기여를 판단하고, 과한 밝기로 실루엣이나 타이밍 결함을 가리지 않는다. 기존 품질 설정과 효과 강도 조절 경로를 존중한다.
- 후처리는 필요한 클라이언트 카메라에 적용한다. 표현 재현을 위해 공격 판정·피해량·게임 시간을 임의로 바꾸지 않는다.

## 비교 검증과 완료

- 콘솔의 컴파일·셰이더 오류를 확인하고 실제 재생한다. 코드 변경은 프로젝트가 요구하는 검증을 수행한다.
- **실제 렌더 캡처는 `execute_code`로 만든다.** 참조와 같은 화각·해상도의 카메라를 코드로 세우고, 효과를 결정적인 시각으로 샘플링해 `RenderTexture`에 그려 PNG로 저장한 뒤 그 PNG를 Read로 본다. 자동 재생 시계에 의존하면 같은 프레임을 다시 뽑을 수 없으므로, 임의 시각을 그대로 표시하는 결정적 샘플링 API를 효과 쪽에 만들어 둔다.
- 같은 상대 시간의 참조와 결과 프레임을 나란히 비교한다. 실루엣, 화면 점유율, 시작·정점·소멸 시간, 색, 움직임, 잔상을 기준으로 조정한다. 단일 정지화면만으로 시간적 유사성을 판정하지 않는다.
- 완료 보고에는 위 품질 기준의 충족 여부와 근거가 되는 참조/결과 비교 캡처 또는 영상을 포함한다. 주요 레이어 누락을 단순한 제외 사항으로 적어 두고 완료 선언을 하지 않는다.
- 실제 게임 카메라와 배경에서 캡처하거나 녹화해 직접 확인한다. 합성 미리보기, 에디터 재생, 실제 플레이 검증을 구분한다. 캡처 또는 사용자 확인이 없으면 시각적 결과는 미검증이다.
- 반복·중첩 재생과 종료 후 잔여 오브젝트·후처리를 검사한다. 성능은 실제 동시 사용량에서 입자 수, 투명 오버드로, 머티리얼·드로콜, 후처리 GPU 비용을 필요한 범위로 측정한다. 측정 없이 최적화 완료라고 보고하지 않는다.
- 참조와의 주요 차이, 결과 프리팹·설정·Meshy 에셋 경로, 비교 캡처, 수행한 검증과 남은 한계를 간결하게 전달한다. 외부 서비스나 에디터가 막혔으면 가능한 산출물을 보존하고 막힌 단계를 명시한다.

## 그믐 저장소에서 적용할 때

- 저장소 루트 기준 `CLAUDE.md`와 `.claude/docs/HANDOFF_CURRENT.md`의 관련 인수인계를 따르고, 전투 VFX면 `docs/unity/COMBAT_VFX_DIRECTION.md` 및 검기 작업에 한해 `docs/unity/SLASH_VFX_DESIGN.md`를 읽는다. 문서보다 현재 코드·에셋을 우선한다.
- 표현 전용 VFX는 클라이언트 표현이다. 서버 판정·피해·타이밍을 시각에 맞추려고 바꾸지 않는다. 네트워크·씬·초기화에 손대면 저장소의 L3(3인) 검증 요구가 붙는다.
- 과거 특정 작업에서 전체 화면 후처리를 제외했다는 기록을 이번 사용자의 후처리 허용을 막는 영구 규칙으로 취급하지 않는다. 소유권·공용 설정·씬 변경은 현재 요청자의 기존 승인 범위와 저장소 지침으로 판단한다.
- 기존 표현 설정·풀·네트워크 표현 통지 경로를 재사용한다. 커밋·푸시는 명시적으로 요청받았을 때만 한다.
