# 모호한 요청 명확화

## Codex 실행 기준

- 먼저 프로젝트 루트의 `AGENTS.md`와 그 문서가 가리키는 `CLAUDE.md`를 따른다. 아래 일반 경로는 프로젝트 루트 기준이고 Markdown 링크는 이 파일 기준이다.
- 팀장 작업이면 `.claude/docs/preferences/TEAM_LEAD_MODEL_WORKFLOW.md`의 모델 분업을 적용한다. 이 스킬 자체가 직접 코딩이나 다른 모델 사용의 예외를 허용하지 않는다. 세션에서 명시된 예외는 해당 범위에만 적용한다.
- 원본의 질문 도구는 Codex의 사용 가능한 사용자 입력 도구로 대응한다. 선택·명확화에는 `request_user_input_async` 또는 제공된 `request_user_input`을 쓰되 현재 도구 제약을 따른다. 승인이 필요한 질문은 승인 요청을 지원하는 채널로 하고, 답변을 받기 전 의존 작업을 실행하지 않는다. 해당 도구가 없으면 일반 대화로 질문한다.
- 기존 대화의 승인과 사용자 지시를 우선한다. 이미 결정된 내용을 재확인하지 않는다. 확인이 필요하면 초안·근거를 먼저 준비하고 이 SKILL.md의 적용 조항을 링크해 이유를 설명한다.
- 읽기는 사용 가능한 파일/셸 도구, 편집은 패치 도구, 명령 실행은 셸 도구를 사용한다. 존재하지 않는 Claude 전용 도구를 호출했다고 주장하지 않는다.

## 언제 발동하나

다음 중 하나라도 해당하면, 코드를 바로 수정/구현하기 전에 이 스킬을 따른다.

- 지시어만 있고 대상이 없음: "이거 고쳐줘", "더 낫게 해줘", "정리해줘"
- 대상은 있으나 범위가 불명확: 어떤 씬/폴더/스크립트인지, 얼마나 넓게 손댈지 불특정
- 구현 방식이 여러 갈래로 갈리고 각각 결과물이 달라짐 (예: 저장 위치, 네이밍 규칙, UI 방식)
- 이 변경이 다른 코드/문서/팀원 작업에 영향을 줄 수 있는데 그 영향 범위가 불확실

`CLAUDE.md`의 의사소통 원칙("사실 · 추정 · 미검증을 구분한다", "코드나 설정을 읽어 확인할 수 있는 것을 질문으로 되돌리지 않는다")과 짝을 이룬다 - 이 스킬은 **추천하기 전에, 애초에 무엇을 추천해야 할지조차 불확실한 경우**를 다룬다.

반대로 다음은 발동 대상이 아니다: 요청이 구체적이고 대상/범위가 명확한 경우, 컨벤션 문서(`docs/coding-convention.md` 등)를 보면 답이 정해지는 경우. 이때는 바로 실행한다 - 매번 확인 질문을 던지면 오히려 방해가 된다.

## 방법

1. **결과를 크게 바꾸는 미확정 요구를 임의 확정하지 않는다.** 기존 문맥·코드·관례로 해결할 수 있는 일상적인 선택은 처리하고, 사용자만 결정할 수 있는 차이만 질문한다. 답에 의존하지 않는 조사와 준비는 계속한다.
2. **무엇이 불명확한지 먼저 코드/문서를 읽고 좁힌다.** 탐색 없이 바로 사용자에게 되묻지 않는다 - 예/아니오로 답할 수 있는 질문은 최대한 스스로 조사해서 없앤 뒤, 정말 사용자만 결정할 수 있는 지점만 질문으로 남긴다.
3. **Codex 사용자 입력 도구로 구체적 선택지를 제시한다.** "어떻게 할까요?" 식의 열린 질문 대신, 조사한 내용을 바탕으로 2~4개의 실제 대안을 제시하고 근거를 덧붙인다. 추천 대안이 있으면 첫 번째 옵션에 "(권장)"을 붙인다. 기술적 트레이드오프가 있는 대안(아키텍처·라이브러리·동기화 방식 등)이면 [present-alternatives](../present-alternatives/SKILL.md)의 장단점 분석 틀을 먼저 적용한 뒤 그 결과를 선택지로 정리한다.
4. **질문은 실행에 필요한 만큼만.** 한 번에 필요 이상으로 여러 질문을 쏟아내지 않는다 - 결정이 서로 독립적이면 한 번에 묶어 물어도 되지만, 뒤 질문이 앞 질문의 답에 따라 달라지면 순서대로 나눈다.
5. **답을 받으면 그 결정을 반영해 계획/코드를 진행한다.** 같은 사안을 다시 묻지 않는다.

## 예시

```
사용자: "이거 커밋 메시지 형식 좀 정리해줘"

❌ 바로 임의로 Conventional Commits 형식으로 재작성
✅ 기존 커밋 로그/문서를 먼저 확인 -> 이미 확립된 관례가 없음을 파악
   -> Codex 사용자 입력 도구로 "타입 태그 스타일(영어 vs 한글)",
      "scope 표기 방식" 등 실제로 결과물이 갈리는 지점만 질문
```
