# 코드 소유권 확인

## Codex 실행 기준

- 먼저 프로젝트 루트의 `AGENTS.md`와 그 문서가 가리키는 `CLAUDE.md`를 따른다. 아래 일반 경로는 프로젝트 루트 기준이고 Markdown 링크는 이 파일 기준이다.
- 팀장 작업이면 `.claude/docs/preferences/TEAM_LEAD_MODEL_WORKFLOW.md`의 모델 분업을 적용한다. 이 스킬 자체가 직접 코딩이나 다른 모델 사용의 예외를 허용하지 않는다. 세션에서 명시된 예외는 해당 범위에만 적용한다.
- 원본의 질문 도구는 Codex의 사용 가능한 사용자 입력 도구로 대응한다. 선택·명확화에는 `request_user_input_async` 또는 제공된 `request_user_input`을 쓰되 현재 도구 제약을 따른다. 승인이 필요한 질문은 승인 요청을 지원하는 채널로 하고, 답변을 받기 전 의존 작업을 실행하지 않는다. 해당 도구가 없으면 일반 대화로 질문한다.
- 기존 대화의 승인과 사용자 지시를 우선한다. 이미 결정된 내용을 재확인하지 않는다. 확인이 필요하면 초안·근거를 먼저 준비하고 이 SKILL.md의 적용 조항을 링크해 이유를 설명한다.
- 읽기는 사용 가능한 파일/셸 도구, 편집은 패치 도구, 명령 실행은 셸 도구를 사용한다. 존재하지 않는 Claude 전용 도구를 호출했다고 주장하지 않는다.

## 언제 발동하나

작업 대상 파일이 요청자 본인의 파트를 벗어나 다른 담당자 영역과 접촉할 때 발동한다. 판단 기준은 `CLAUDE.md`의 "작업 범위" 절과 `.github/CODEOWNERS`다 — 이 스킬은 그 두 문서를 실제로 적용하는 절차다.

**요청자가 팀장(@AidenKim923)이면 이 스킬의 승인-질문 절차(3번)를 건너뛴다.** `CLAUDE.md` "작업 범위" 절에 따라 팀장은 전 영역에 권한이 있다. 대신 이번 변경이 [CLAUDE.md의 "프로젝트 구조 변경"](../../../CLAUDE.md) 목록에 해당하는지만 확인하고, 해당하면 무엇이 바뀌는지 짧게 알린 뒤 그대로 진행한다 — 막지 않는다. 해당하지 않으면 알릴 것도 없이 바로 진행한다.

다른 팀원이 요청자일 때는 구체적으로 다음을 건드리기 직전 이 스킬 전체 절차를 따른다:

- `Assets/00.Scenes/Main.unity` (통합 씬)
- 요청자 본인 파트가 아닌 `Assets/01.Scripts/` 하위 폴더 (예: 네트워크·전투 담당이 `03.AI/`를 고침)
- `.gitattributes`, `.gitignore`, `.github/` 등 저장소 공용 설정
- 네트워크 권위 경계를 바꾸는 변경 (서버 판정 ↔ 클라 로컬 처리 전환)
- 외부 에셋 원본 (`Assets/98.FreeAssets/`, `Assets/99.ThirdParty/`, `Assets/Mirror/` 등)
- 파일 삭제, 대량 이동, 이름 일괄 변경
- 다른 사람의 작업 씬 (`Dev_*.unity`)

`CLAUDE.md` 작업 범위표에서 "승인 없이 수정 가능"에 해당하는 영역(자기 파트 `Assets/01.Scripts/`, `Assets/09.Data/` SO 값, `docs/`)은 이 스킬 대상이 아니다 — 바로 진행한다.

## 방법

1. **건드릴 파일 목록을 먼저 확정한다.** 편집을 시작하기 전에 이번 작업이 실제로 어떤 경로를 건드리는지 훑는다.
2. **`.github/CODEOWNERS`로 소유자를 확인한다.** 해당 경로의 담당(팀장/AI담당/시스템담당/아트담당)이 지금 요청한 사람과 다른지, 혹은 통합 담당(팀장) 승인이 필요한 영역인지 확인한다.
3. **CLAUDE.md 작업 범위표에서 등급을 확인한다.**
   - **승인 후 수정** 영역이면: 이미 담당자 승인을 받았는지 사용자에게 묻는다. 받았다고 확인되면 진행하고, 안 받았으면 먼저 확인부터 하고 오도록 안내한 뒤 **여기서 멈춘다.**
   - **수정 금지** 영역(다른 사람의 `Dev_*.unity`, `Library/`/`Temp/` 등 생성물)이면: 기본적으로 거절한다. 사용자가 명확한 사유와 함께 강행을 요청하면 그 사유를 다시 확인한 뒤에만 진행한다 — 그냥 지나가지 않는다.
4. **직접 그 담당자에게 연락할 수단이 없다.** 이 스킬은 Codex가 팀원에게 대신 연락하는 게 아니라, 사용자가 실제로 확인했는지 확인하는 절차다. Codex 사용자 입력 도구로 "이미 담당자 확인받음 / 지금 가서 확인하고 올게 / 그래도 진행해줘(사유 설명)" 형태로 묻는다.
5. **범위가 애매하면(예: 공용 유틸리티처럼 특정 파트에 안 걸리는 코드) CODEOWNERS에 명시적 규칙이 없는지 먼저 확인**하고, 그래도 애매하면 사용자에게 확인한다 — 임의로 안전한 쪽으로 넘겨짚지 않는다.
6. 확인을 통과했으면 이후 작업에서는 같은 파일 범위에 대해 다시 묻지 않는다.

## 예시

```
요청: "AI 담당인데, 패링 판정 로직도 같이 손보고 싶어" (Assets/01.Scripts/02.Combat/ 수정 필요)

❌ 바로 Combat 폴더 코드를 고침
✅ CODEOWNERS 확인 → /Assets/01.Scripts/02.Combat/ 은 팀장(@AidenKim923) 소유
   → CLAUDE.md 작업 범위표: 다른 파트 Scripts 폴더 = "승인 후 수정"
   → Codex 사용자 입력 도구로 "팀장 확인받으셨나요?" 확인 후 진행
```
