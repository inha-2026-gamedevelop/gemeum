# 패링과 반격 표식 — 현재 구현 계약

2026-09-22 코드 기준. 원본은 `Assets/01.Scripts/02.Combat/Parry/ParryController.cs`, `ParryJudge.cs`, `ParryGauge.cs` 및 `02.Combat/Player/PlayerAttack.counter.cs`다.

## 현재 보상

패링 성공은 이번 시도에 지불한 스태미나와 특성 보너스를 환급한다. 같은 공격 실행의 서로 다른 타격을 받아내면 반격 표식을 최대3개까지 기록하고, 검의 받아베기 R이 예약·소비한다. 기본 유지2초, 공격 종료 후 유예1.2초는 CombatConfigSO의 CounterDuration/CounterEndGrace 원본을 따른다. 특성은 이 값을 변경할 수 있다.

구 0~100 패링 게이지와 다음 공격 치명 보상 API는 코드에 일부 남아 있으나 현재 패링 성공·공격 입력 경로의 활성 규칙이 아니다. 성공 시 별도 추가 무적을 지급하는 구 계약도 현재 보상으로 설명하지 않는다. 일반 R과 반격 R의 조건·쿨다운은 구분한다. [검·활 구현](SWORD_BOW_REWORK_IMPLEMENTATION.md).

## 입력·window 계약

1. 공격 실행자가 대상 `IParryWindowTarget`에 공격자·window 키와 절대 서버 시각 구간을 연다.
2. 소유 클라이언트가 관찰한 window와 입력 순서·시각을 요청한다.
3. 서버가 소유자, 생명/행동/무기, 자원, 요청 순서, window 일치·소비 여부와 입력 시각을 검증한다.
4. RTT 기반 보정에는 서버가 정한 하한/허용 범위를 적용한다. 클라이언트가 임의의 과거 시각을 보내 성공을 확정하지 못한다.
5. `ParryJudge`가 보정된 발동 시각과 서버 window를 비교한다. 소비 기록(tombstone)으로 같은 공격의 재전송 보상을 막는다.
6. 성공 시 표식·환급·`OnParried`를 처리하고 결과를 전달한다. 실패 시 후딜과 결과 코드를 적용한다.

수치 원본은 CombatConfigSO와 관련 네트워크 상수다. 문서의 목표 지연 수치가 실제 네트워크 측정값이라는 의미는 아니다.

## 공격 실행자 의무

`ChanggwiBrain`, `Phase1State`, `Phase2State` 등의 실행 경로는 공격 취소·종료·대상 소실에 열린 window를 닫아야 한다. 같은 공격 실행의 연속 타격과 새로운 공격 실행을 구별한다. 보스의 일반 흘려내기와 패턴을 끊는 특수 카운터는 동일한 결과로 처리하지 않는다. 현재 보스 정책과 타격별 허용 여부는 [보스 패턴](BOSS_PATTERN_CONTRACT.md)을 따른다.

## 표식 취소와 표현

- 표식은 대상·공격 실행·수명에 연결된다. 이전 적의 표식을 다른 공격으로 무조건 이어 붙이지 않는다.
- 피격, 상태 전환, 무기 변경과 예약 취소를 검·활 구현 및 서버 코드와 함께 확인한다. HP 피해와 경직 저항은 서로 다른 조건이다.
- UI는 `ParryGauge`의 CounterMarks/CounterRemaining 등 공개 상태를 읽는다. 서버 수락 전에 보상을 확정하지 않는다.
- 모션·VFX는 서버 cue/결과에 맞추고 애니메이션 이벤트를 패링 판정의 원본으로 사용하지 않는다.

## 검증 기준

유효 window/빠른 입력/늦은 입력/잘못된 키/중복 요청/종료된 공격/자원 부족/다른 무기/사망·정지/연속 타격을 확인한다. 표식1~3, R 예약과 소비, 대상 소실·피격·무기 변경 후 취소를 호스트와 참가자에서 비교한다.

관련 EditMode 규칙 검사와 대표3프로세스 검증 기록은 있지만, 실제 보스 입력의 사람 체감·외부회선 PC3대·고지연/손실을 전부 검증한 것은 아니다. 변경 시 [멀티플레이 절차](../ai/04_MULTIPLAYER_TEST_PROTOCOL.md)에 조건과 결과를 남긴다.
