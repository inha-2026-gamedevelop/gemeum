# 로비 무기 선호 · 공격 조준과 개발 표시

## 로비에서 출발하기

1. Steam 경로는 `Builds/Development/run-steam-lobby.bat`로 실행하고 방을 만들거나 참가한다. **사람을 기다리는 Steam 대기방에서부터** 검·차사 / 활·신궁 / 방울·무녀를 선택할 수 있다. 한 명만 있어도 선택 가능하다.
2. 세 명이 모이면 방장이 **시작**을 누른다. Mirror 로비 씬에 도착하면 **출발 준비** 화면이 열리고, 대기방에서 고른 선호가 서버 요청으로 전달된다. 여기서는 서버 로스터의 선택·준비 상태를 표시한다. KCP 직접 접속도 이 화면에서 선택할 수 있다.
3. 선호를 최종 확인하고 각자 **준비 완료**를 누른다. 세 명 모두 준비되면 서버가 역할을 배분하고 런을 시작한다.

Steam 대기방의 멤버 선호는 표시용 자기 신고이며 역할 확정이 아니다. 본인의 선택은 현재 방에서만 보관하고, 나가거나 다른 방에 들어가면 초기화한다. 서버 연결 후 로비 씬과 본인 슬롯 동기화가 끝나면 `LobbyController`가 기존 요청 API로 한 번 전달한다. 이미 서버에서 선택한 선호가 있으면 덮어쓰지 않는다.

같은 무기를 선호할 수 있다. 중복 선호는 기존 서버 배분 규칙에 따라 추첨하며, 시작 무기는 검·활·방울 한 명씩이다. 선호를 바꾸면 해당 사람의 준비가 취소된다. 준비 취소 버튼으로 대기할 수 있다. 선택하지 않고 준비하면 기존 무작위 배분에 참여한다.

`SessionManagers.prefab`의 `_devAutoReady`는 껐다. 개발 테스트 창에서 명시적으로 자동 준비를 켜면 이 대기 단계를 건너뛸 수 있다.

### 팀원이 사용하는 API

- `SteamLobbyService.RequestWeaponPreference(WeaponKind)` — Mirror 접속 전 Steam 대기방의 선호 보관·표시. `TryGetLocalWeaponPreference`, `TryGetMemberWeaponPreference`로 조회한다. 이 값으로 무기를 직접 지급하지 않는다.
- `LobbyController.RequestWeaponPreference(WeaponKind)` — 선호 요청. `true`는 전송 성공이며 서버 확정을 뜻하지 않는다.
- `LobbyController.RequestReady(bool)` — 준비·취소 요청.
- `LobbyRoster.SlotCount`, `GetSlot(index)` — 선호·준비 상태 조회. `LobbySlot.PlayerNetId`로 현재 로컬 플레이어와 표시를 연결한다. 서버가 로비 씬 도착 시 교체된 플레이어 번호를 갱신한다.
- 호출자 식별·로비 단계·입장 잠금·enum 검증과 준비 취소·배분은 서버가 담당한다. 클라이언트가 슬롯을 직접 수정하지 않는다.

## 활의 조준

일반 사격도 화면 중심 카메라 ray를 서버에 보내고, 서버가 검증한 조준점으로 화살을 발사한다. 어깨 옆 카메라 방향과 평행하게 쏘던 경로를 수정했다. 발사점은 캐릭터의 기존 SO 총구 높이·전방 거리이며, 그곳에서 조준점으로 수렴한다. 가까운 목표에서는 발사점과 화면 중심의 위치가 다른 것이 정상이다.

일반·정밀 사격 모두 `ArrowAimGeometry.BuildCameraRay`를 사용한다. 서버가 카메라 입력의 유한성·정규화·플레이어와의 거리를 검사하고 목표점은 서버 물리 쿼리로 결정한다. 자기 콜라이더는 조준 대상에서 제외한다. 기존 락온 보정과 충돌 판정은 유지한다.

`PlayerAttack.RequestAttack()`은 로컬 소유자·입력 허용 여부를 검사하고 이 경로로 기본 공격을 요청한다.

## 공격 범위 기즈모와 로그

| 무기 | 기본 공격 기즈모 | 우클릭 요청 로그 |
|---|---|---|
| 검 | 서버가 판정한 근접 부채꼴 | `[우클릭] 검: 패링 요청` |
| 방울 | 서버가 판정한 범위. 360도 설정이면 원 | `[우클릭] 방울: 치유 요청` |
| 활 | 실제 발사점·방향·최대 이동 거리의 선과 충돌 반경 | `[우클릭] 활: 정밀 사격 홀드 요청` |

공격 기즈모는 자기 공격만 1.5초 표시한다. 원격 클라이언트도 서버가 보낸 판정값으로 그린다. 활 표시는 발사 당시 예상 직선이며, 이후 락온 유도·벽 충돌로 궤적과 이동 거리가 달라질 수 있다.

개발 도구 잠금 해제는 기존 **Home → PageUp → PageDown → End** 순서다. 기즈모 전체 표시와 Combat 채널을 켠다. 우클릭 로그는 해당 무기의 요청 시점에 남으며 서버 수락과 구별한다. 활·방울 사용자는 검 패링 요청을 함께 보내지 않는다.

일반 공격의 **공격 거부·공격 헛침 로그**를 제거했다. 거부 상태 이벤트, 실제 판정, 적중 피드백과 필수 구성 오류 진단은 유지한다.

## 검증

### Steam 대기방 누락 수정 (2026-09-15 추가)

- 기존 UI가 Mirror 연결 후 로비에만 표시되어 Steam `Gathering` 대기방에서 선택할 수 없었다. 개발용 빌드가 오래된 문제가 아니었다.
- Steam 대기방에 무기 선택을 추가했다. 에디터에서 실제 Steam 방 생성 → 활 버튼 콜백 → 자기 멤버 데이터 조회 → Steam 호스트 연결 → 서버 로스터 `Singung` 반영과 준비 미완료 유지 → 방 나가기 시 선호 초기화를 확인했다. 호스트 전달 확인은 개발 인원 설정 1명으로 실행했고, 종료 시 설정을 복원했다.
- 전환 시 Steam 대기방의 임시 EventSystem을 해제하여 런 EventSystem과 중복되지 않도록 했다. 전환 전후 활성 EventSystem 1개를 확인했다.
- EditMode 479개 중 478 통과·0 실패·기존 NavMesh 1 제외.
- **로컬 개발 빌드 갱신**: 성공, 40.1초. 보고서 오류 1·경고 34이며 오류는 기존 외부 WeatherMaker 물 셰이더 `UnityTessellationFactors`다. C# 컴파일 오류는 없다. 기존 빌드 메뉴의 부가 파일 복사도 실행했다.
- 해당 개발 빌드 3개로 KCP 17929 테스트: 선호 선택, 준비 후 선호 변경 시 대기 유지, 최종 준비 후 Field/RunId 1 전환, 검·활·방울 배분을 확인했다.
- 해당 실행 파일의 Steam 경로에서 방 생성 후 **Gathering 1/3명 상태의 무기 버튼 표시**를 1280x720 캡처로 확인했다. 에디터 버튼 콜백 검증과 별개로, 네이티브 실행 파일의 실제 마우스 클릭·Steam 원격 3PC 전달은 미검증이다.
