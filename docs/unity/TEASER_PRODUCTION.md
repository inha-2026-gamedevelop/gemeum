> 🔒 **실촬영·Recorder 연동은 10월 15일 이후다.** ([티저 영상 설계 1장](TEASER_DESIGN.md))

- **Remotion 미리보기:** `tools/teaser`에서 `npm.cmd ci`, `npm.cmd run studio`. `TeaserPlan`은 샷 이름·자막·타이틀·소리 지시, `TeaserReview`는 등록한 원본 클립·음원을 재생한다. 원본은 현재 없으며 누락 안내를 표시한다. 최종 티저가 아니다.

- **마감/검사:** `master:audio`, `inspect:master`. 2패스 음량 보정·AAC 후 재측정·규격/48초 대비 검사. 실제 BGM·대사 믹스는 아직 아니다.
- 실행법과 데이터 계약: [tools/teaser/README.md](../../tools/teaser/README.md). 브라우저 DevPanel 조작, HUD 숨김/복원, 녹화기, 게임 연출과 실제 원본 조립/최종 믹스는 남아 있다.

## 1. 목표

**샷을 고치면 그 샷만 다시 녹화하고, 편집을 고치면 3D를 다시 렌더하지 않고 재조립만 한다.**
After Effects처럼 사람이 타임라인을 손으로 맞추는 대신, 샷과 편집을 데이터와 코드로 남겨 몇 번이든 같은 결과를 다시 만든다.

| 산출물 | 규격 |
|---|---|
| 마스터 영상 | 1920×1080 · 60fps · H.264 |
| 길이 | **72~73초** (타이틀 정지를 3~4초로 늘린 결과. 허용 범위 60~75초 안) |
| 음량 | 통합 **−14 LUFS**, 트루 피크 **−1 dBTP 이하** |

### 1.1 레퍼런스 실측 — 벨가르딘 티저

로스트아크 「죽음의 계율자, 벨가르딘」 티저(4분 50초, 720p · 30fps 원본)를 ffmpeg로 측정했다. 영상 사본과 추출 프레임은 저장소 밖 임시 폴더에서만 쓰고 분석 후 지웠다.

| 구간 | 시간 · 비율 | 컷 | 색 | 음량 |
|---|---|---|---|---|
| 흑백 수묵 회상 | 0~70초 · 24% | **0개.** 먹 번짐 전환이 2.5~3.5초 걸린다 | 채도 1~2. **노란 꽃만 색이 있다** | −16~−17 LUFS |
| 현재 · 인물 | 70~99초 · 10% | 2개 | 차가운 컬러로 넘어간다. 같은 꽃이 다시 나온다 | −17~−18 |
| 전환점 | 99~103초 · 1% | **검은 화면 약 3초** | 없음 | **−20~−23 (약 6 LU 하강)** |
| 게임플레이 몽타주 | 103~231초 · 44% | **30초당 9컷(평균 3초)으로 가장 빠르다.** HUD 없음 | 보라 · 청록 | −13 유지 |
| 클라이맥스 | 231~285초 · 19% | **오히려 긴 샷(37초 · 18초)** | 빨간 장판에서 따뜻한 색이 **딱 한 번** 튄다 | −12.5 (최고) |
| 타이틀 카드 | 285~290초 · 2% | **5초 정지** | 키아트 | −19로 내려간 뒤 무음 |

전체 음량은 −14.1 LUFS, 음량 범위(LRA)는 5.1 LU로 **매우 압축돼 있다.** 앞뒤를 빼면 무음 구간이 없다.

**측정 한계.** 장면 검출은 디졸브를 못 잡으므로 0~70초의 "컷 0"은 샷이 하나라는 뜻이 아니라 먹 전환으로 이어졌다는 뜻이다(프레임을 직접 보고 확인). 따뜻함 지수(V−U 평균)는 화면 평균이라 작은 색 면적은 반영이 약하다.

### 1.2 가져오는 것과 가져오지 않는 것

| 가져온다 | 우리 티저에서 |
|---|---|
| **상징 오브젝트를 먹 전환의 기준점으로** — 꽃의 화면 위치를 고정한 채 주변만 먹으로 바뀐다 | 0:04 갓 클로즈업 → 0:09로 넘어갈 때 갓을 고정. 1막이 25초라 전환은 **1.5~2초** (비율대로 줄이면 0.7초라 읽히지 않는다) |
| **전환점은 완전 무음이 아니라 음량 급감** | 0:48 "BGM 급정지 → 바람 소리만"이 이미 같은 문법이다. 대비는 벨가르딘의 6 LU보다 크게, **15 LU 이상** |
| **게임플레이는 HUD를 끄고 빠르게** | 2막 잡귀 교차 **1초 이하**, 패링 **0.5초**. HUD 숨김 명령이 필요하다(3장) |
| **가장 격렬한 순간은 끊지 않는다** | 0:58 꼬리 펼침 + 오케스트라 폭발을 **4초 이상 한 샷**으로. 실시간 연출이라는 증거가 된다 |
| **색은 한 번만 튄다** | 3막 여우불 청록이 처음으로 화면을 채워야 한다. **0:40의 청록 첫 등장은 작은 면적**으로 |
| **타이틀은 멈춰 둔다** | 1:08 먹 덮기 → 「그믐 (晦)」을 **3~4초 정지** |

| 가져오지 않는다 | 이유 |
|---|---|
| 90초 내내 이어지는 내레이션 자막 | 우리 원칙은 자막 한 줄 + 육성 한 줄이다([티저 영상 설계 6.2](TEASER_DESIGN.md)) |
| 게임플레이가 영상의 절반을 넘는 비중 | 70초는 서사 곡선에 쓴다 |
| 보스의 비극적 과거 회상 | [티저 영상 설계 2.1](TEASER_DESIGN.md)에서 기각했다 |
| 음량 범위 5 LU 수준의 압축 | 무음 대비가 우리 티저의 핵심이라 범위를 넓게 둔다. 통합 −14 LUFS만 맞춘다 |

## 2. 권위 경계

**티저는 원격 참가자 없이 촬영한다.** 전투 컷은 로컬 Mirror Host 한 명이 실제 서버 판정을 실행하고, 연출 컷은 표현 대상만 둔 준비 환경을 사용할 수 있다. Mirror 자체를 끈다는 뜻이 아니다. 개발 명령으로 테이크를 준비하되 서버 판정·시계를 촬영 편의로 수정하지 않는다.

**`Time.timeScale`은 전체 게임의 시계를 바꾸지 않는다.** 현재 Mirror `NetworkTime`은 unscaledTime, 일부 VFX 회수도 unscaledDeltaTime 기준이다. 전투 샷의 데이터는 timeScale=1만 허용한다. 슬로우는 표현 전용 컷에서 별도 검증하거나 후반 편집으로 처리하며 출력 프레임과 시뮬레이션 시간을 구분한다.

그래도 **게임 코드의 경로는 바꾸지 않는다.**

- 촬영 도구는 전부 `#if UNITY_EDITOR || DEVELOPMENT_BUILD || GEUMEUM_DEVTOOLS` 안의 개발 도구로만 만든다. 제품 코드가 촬영 코드를 참조하지 않는다([프로젝트 구조 설계서](../04-architecture.md)의 `Dev/` 원칙).
- 서버 판정이나 동기화 방식을 촬영 편의 때문에 고치지 않는다. 필요한 조작은 개발 패널의 명령으로만 건다.

**화면 안과 밖의 경계**([티저 영상 설계 9장](TEASER_DESIGN.md))는 도구로 나눈다.

| | 무엇 | 도구 |
|---|---|---|
| **화면 안** | 캐릭터 · 아레나 · 이펙트 · 패링 · 갓 낙하 · 먹 번짐(1:02) | **Unity Recorder 원본만** |
| **화면 밖** | 자막 · 타이틀 · 전환 오버레이 · 오디오 믹스 | Remotion |

**Remotion 레이어에 게임 오브젝트나 게임 이펙트를 그리지 않는다.** 한 컷이라도 섞이면 인게임 컷까지 의심받는다.

```

                                                              │
                     ┌────────────────────────────────────────┤
                     ▼                                        ▼
            TeaserShotPanel (새로)                     PlaytestPanel (있음)
            · 샷 불러오기 / 카메라 포즈 적용·저장        · 배속 0.05~3배 · 일시정지
            · HUD 숨김                                   DevCheatPanel (있음)
            · 연출 트리거 (갓 낙하·꼬리·먹·페이즈)       · 무한 자원
            · 녹화 요청 ──▶ Editor 녹화기 ──▶ Unity Recorder
                     ▲
            teaser-shots.json (샷 데이터, 단일 원천)
                     │
                     ▼
            Remotion 프로젝트 ── 같은 JSON으로 샷 시각을 읽는다
```

**주의 — 녹화 제어는 Editor 폴더에 둔다.** Recorder는 에디터 전용 어셈블리라 런타임 스크립트가 직접 참조할 수 없다. 런타임 패널은 녹화 요청만 정적 훅에 올리고, `[InitializeOnLoad]` Editor 스크립트가 그 훅을 받아 `RecorderController`를 돌린다. 착수 시 컴파일로 확인한다.

**주의 — HUD는 UI 파트 소유다(@kjw1237).** HUD 숨김은 UI 코드를 고치지 않고 런타임에 캔버스만 끄는 방식으로 하되, 어떤 캔버스를 끌지는 담당자와 합의한다.

## 4. 데이터

### 4.1 샷 데이터 — 단일 원천

**샷의 시각과 길이는 한 파일에만 적는다.** Unity가 그 값으로 녹화하고 Remotion이 같은 값으로 조립한다. 두 곳에 따로 적으면 반드시 어긋난다.
수치를 코드 상수로 박지 않는 이유는 [밸런스 데이터 작업](BALANCE_DATA_WORKFLOW.md)과 같다 — 촬영 중에 계속 고친다.

| 필드 | 뜻 |
|---|---|
| `id` | 샷 식별자. 예: `A1-04-gat` |
| `act` · `startFrame` · `durationFrames` | 막, 티저 출력 기준 시작/길이. 60fps 정수, 구간은 시작 포함·끝 제외 |
| `scene` | 녹화할 씬 |
| `cameraFrom` · `cameraTo` | 월드 position/euler/FOV. null은 미설정. Editor 창에서 저장 |
| `timeScale` | 표현 배율. 전투는 1만 허용, 현재 실행기는 없음 |
| `hideHud` | HUD 숨김 여부 |
| `triggers` | `kind`, `offsetFrame`, `clock: output`. 샷 출력 프레임 기준. 현재 실행하지 않음 |
| `sourceInFrame` · `handleFrames` | 원본 사용 시작, 향후 녹화 앞뒤 여유 프레임 목표 |
| `warmupFrames` · `seed` | 촬영 전 물리 안정화·난수 기준. 현재 데이터만 보관 |
| `setupStatus` · `setupNote` · `requirements` | 배우·환경 초기 상태의 준비 여부·메모·선행 조건 |
| `takes` · `selectedTakeId` | 원본 ID/path/fps/frameCount/origin 목록과 선택 ID. 현재 미준비 |

이동 `curve`, `dof`, `grade`, 매치컷 `anchor`는 후속 실행기에서 추가할 필드이며 현재 JSON 스키마에는 없다. 매치컷은 화면 좌표뿐 아니라 크기·회전·실루엣과 다음 샷에 갓이 남는 구도를 함께 맞춘다.

전환은 현재 `overlays`의 절대 출력 프레임으로 얹어 전체 길이를 줄이지 않는다. 68~69초는 먹 덮기 예정 구간, 69~73초는 타이틀 정지다. Remotion overlap 전환을 사용하면 겹침 길이를 별도 계산해야 한다. 36.5~40초의 반격은 미지정 구간을 채운 **임시 편집안**이며 실제 촬영 전 확정한다.

후속 실행기는 `Prepare → Warmup → Record → Restore`를 따른다. 취소·실패·Play 종료에도 기존 카메라 제어·HUD·배속·렌더 설정을 복원한다. 현재 준비 창은 이 상태들을 바꾸지 않는다.

## 7. 검증

| 항목 | 기준 | 방법 |
|---|---|---|
| 파이프라인 | 더미 5초 마스터가 끝까지 나온다 | 2단계 산출물 |
| 샷 재현성 | 같은 샷 데이터로 두 번 녹화하면 카메라 포즈와 트리거 시각이 같다 | 두 테이크를 나란히 비교. 파티클 난수 때문에 픽셀 완전 일치는 기대하지 않는다 |
| 화면 안 규칙 | 게임 화면은 전부 Recorder 원본에서 나온다 | 편집 데이터의 클립 목록과 녹화 파일 대조 |
| 길이 | 72~73초 | `ffprobe` |
| 음량 | 통합 −14 ± 0.5 LUFS, 트루 피크 −1 dBTP 이하, 0:48 전후 15 LU 이상 | 아래 음량 명령 |
| 리듬 | 2막 잡귀 컷 1초 이하, 0:58 샷 4초 이상 | 아래 컷 명령 |
| 색 | 청록이 3막 전에 화면을 채우지 않는다 | 아래 색 명령 + 사람 검수 |
| 시각 결과 | 먹 매치컷 · 타이틀 · 전체 흐름 | **사람 검수.** 확인 없이는 미검증으로 둔다 |
| 라이선스 | 화면과 소리에 나오는 에셋의 증빙이 채워져 있다 | [외부 에셋 라이선스 기록](../licenses/THIRD_PARTY_ASSETS.md). **공개 영상도 배포다** |

**측정 명령** — 1.1절 레퍼런스 분석과 같은 명령으로 우리 결과물을 잰다.

```bash
# 컷 시각
ffmpeg -i teaser.mp4 -an -vf "scale=320:-1,select='gt(scene,0.28)',metadata=print:file=scenes.txt" -f null -
# 밝기 · 채도 · 따뜻함 (초당 2회)
ffmpeg -i teaser.mp4 -an -vf "fps=2,scale=320:-1,signalstats,metadata=print:file=stats.txt" -f null -
# 음량 곡선 · 무음
ffmpeg -i teaser.mp4 -vn -af "silencedetect=n=-40dB:d=0.5,ebur128=peak=true:metadata=1,ametadata=print:key=lavfi.r128.S:file=loud.txt" -f null -
# 5초 간격 콘택트 시트
ffmpeg -i teaser.mp4 -an -vf "fps=1/5,scale=320:-1,tile=6x5" -frames:v 1 sheet.png
```

> ⚠️ **한글이 들어간 경로는 Git Bash에서 ffmpeg로 넘길 때 깨진다**(`Illegal byte sequence`). 영문 이름으로 복사한 사본을 입력으로 쓴다.

음량은 최종 오디오 인코딩을 마친 파일로 다시 측정한다. 구현한 자동 검사는 **45~48초 / 48~51초를 각각 atrim한 3초 구간의 integrated loudness 차이 ≥15 LU**를 사용한다. M/S 곡선은 위 명령으로 보조 검수한다. 컷 길이의 정본은 편집 JSON이며 장면 검출 명령은 플래시 오검출·디졸브 누락이 있는 보조 검사다. 음량/기술 검사 통과가 영상 미술·권리 승인까지 뜻하지 않는다.

## 8. 대안

| 대안 | 기각 이유 |
|---|---|
| **After Effects** | [9장](TEASER_DESIGN.md)상 화면 밖에는 허용되지만, 편집을 데이터로 남겨 반복한다는 1장 목표에 맞지 않는다 |
| Unity Timeline에서 전부 조립 | 게임 셰이더를 전환에 바로 쓰지만, 자막 · 타이밍을 고칠 때마다 3D를 다시 렌더해야 한다 |
| Revideo | MIT라 라이선스 걱정이 없지만 커뮤니티가 작고 유지보수 상태를 확인하지 못했다. **Remotion 무료 조건을 벗어나면 옮길 후보**로 둔다 |
| HTML + GSAP 직접 | 가장 가볍지만 프레임 정확한 헤드리스 캡처를 직접 만들어야 해 결국 Remotion을 다시 만든다 |
| ffmpeg 스크립트만 | 미리보기가 없고 타이틀 모션 표현이 약하다. 마감 보조로만 쓴다 |

**라이선스.** Remotion 무료 라이선스는 개인과 **3인 이하** 조직까지이고, 협업 조직과 일하면 인원을 합산한다. 팀이 정확히 경계선이다. **성우 녹음이 외부 조직과의 협업에 해당하는지 착수 전에 확인한다.** 조건은 [외부 에셋 라이선스 기록](../licenses/THIRD_PARTY_ASSETS.md)에 있다.
