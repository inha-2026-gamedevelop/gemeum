# 보스 트라이 모드 — 30분을 건너뛴다

**2026-09-04 신설.**

---

## 1. 왜 필요한가 — 관객이 다르다

**그믐은 상용 출시가 아니라 포트폴리오다.** 이 한 문장이 난이도와 접근성의 전제를 바꾼다.

| | 상용 게임이라면 | **포트폴리오라면** |
|---|---|---|
| 관객 | 돈을 낸 플레이어 | **심사자 · 전시 관람자 · 팀 자신** |
| 쓰는 시간 | 수십 시간 | **10~15분** |
| 실력 | 자발적으로 는다 | **늘지 않는다. 한 번 보고 간다** |
| 성공 = | 재플레이 | **"이 팀은 만들 줄 안다"** |

**보스까지 최대 30분이 걸린다.** 심사자는 그것을 걷지 않는다. 그러면 [8.3분짜리 클라이맥스](../class-identity-and-boss-2026-09-03.md) — 꼬리 펼침, 아레나 교체, 3인 동시 기믹 — 는 만들어놓고 아무도 보지 못하는 것이 된다.

**보스 트라이 모드는 편의 기능이 아니라 이 프로젝트에서 가장 많이 보여질 화면이다.**

부수 효과로 **난이도 문제도 함께 푼다.** 테스터가 실패해도 30분을 다시 걷지 않으므로, 판정 창을 넓히는 것보다 훨씬 관대하면서 **메커닉을 훼손하지 않는다**(6장).

---

## 2. 저장하지 않는다

**세이브 데이터를 만들지 않는다.** CLAUDE.md는 *"세이브 데이터 마이그레이션은 이 프로젝트에 없다. 영속되는 것은 리더보드 점수뿐"*으로 못 박고 있고, 현재 `GameDB`는 **읽기 전용 SO 접근점이며 쓰기 경로가 0개**다.

런 상태를 직렬화해 복원하는 방식은 기각한다 — 매니저 다섯의 상태·플레이어 상태·잡귀 배치를 전부 저장해야 하고, 그것은 [8.2](../class-identity-and-boss-2026-09-03.md)가 피하려던 작업이다.

**대신 런을 복원하지 않고 건너뛴다.**

```
로비에서 직업 선택
  → 그 직업 그대로 10레벨로 시작
    → 전실(Antechamber)에서 자원 편성
      → 보스전
        → 정산 (리더보드 미등록)
```

**저장 0. 마이그레이션 0.** 필요한 것은 편성 예산과 카탈로그를 담은 SO 하나뿐이며, 이는 밸런스 데이터와 같은 작업이다.

## 3. 전실 (Antechamber)

**`Boss_Arena.unity` 안에 전실을 둔다. 새 씬을 만들지 않는다.**

```
Boss_Arena.unity
├ Antechamber    전실. 게이트 통과 직후 도착 지점
├ Arena_Phase1   산속 사당 · 등불 · 담장       (시작 시 활성)
├ Arena_Phase2   저승 물길 · 여우불 · 얼굴들    (시작 시 비활성)
└ Shared         바닥 콜라이더 · NavMesh · 스폰 마커 · 게이트
```

**전실은 트라이 전용 공간이 아니다. 정식 런도 지나간다.**

| | 정식 런 | 보스 트라이 |
|---|---|---|
| 도착 경로 | 게이트 30초 카운트다운 후 전원 강제 이동 ([8.3](../class-identity-and-boss-2026-09-03.md)) | 로비에서 직행 |
| 전실에서 하는 일 | **3인 도착 확인 → 자동 진행** | **편성 UI → 전원 준비 시 진행** |
| 씬 신설 | 0 | 0 |
| UI 신설 | 0 | 편성 패널 1개 |

**정식 런에도 이득이 있다.** 현재 설계에는 씬 전환 직후 3인이 모두 로드되었는지 확인하는 구간이 없다. 한 명의 로딩이 느리면 **혼자 보스 앞에 떨어진다.** 전실이 그것을 흡수한다.

## 4. 편성은 자유가 아니라 배분

### 4.1 자유롭게 열면 밸런싱이 거짓말을 한다

트라이 모드는 **보스 밸런싱의 주된 도구**가 된다. 그런데 편성을 무제한으로 열면 사람들은 정식 런에서 결코 나올 수 없는 조합으로 보스를 수십 번 두들기고 "괜찮다"고 결론 낸다. 30분을 걸어온 실제 플레이어는 전혀 다른 게임을 만나게 된다.

### 4.2 `BossTrialLoadoutSO`

```
BossTrialLoadoutSO
├ 시작 레벨            10 고정
├ 편성 포인트 상한      N     ← 필드 30분 지점의 기대 획득량
├ 아이템 카탈로그       보스 앞에서 실제로 가질 수 있는 것만
├ 물약 개수 상한        정식 런 기대값 (7.2 소지 제한과 일치)
└ 특성 포인트           10레벨 기준
```

**"무엇이든 준다"가 아니라 "30분치를 네가 나눠 쓴다"이다.**

수치는 코드에 박지 않고 SO에 노출한다 (CLAUDE.md 밸런스 데이터 규칙). **정식 런 실측 전에는 임시값을 두고, 실측 후 `N` 하나만 조정한다.**

**부수 효과 — 트라이 모드가 정식 런보다 재미있을 수 있다.** 30분간 주워 걸린 것을 쓰는 것이 아니라 직접 고르기 때문이다. 이는 결함이 아니라 밸런싱 도구로서 바람직한 성질이다.

## 5. 리더보드 미등록

**트라이 모드의 결과는 리더보드에 등록하지 않는다.** 30분의 이동·파밍·결계 회피가 빠진 기록은 정식 런과 같은 축에 놓을 수 없다.

**단, 점수는 표시한다.** 표시하지 않으면 밸런싱 도구로 쓸 수 없다.

```
        연습 기록 · 미등록
        효율 점수 1,840
        순위표에 오르지 않습니다
```

[11장 효율 채점](../02-game-design.md)의 계산식은 그대로 쓰고 등록 경로만 끊는다.

---

## 6. 난이도 — 판정이 아니라 실패 대가를 완화한다

테스터의 컨트롤 수준이 액션 게임 숙련자에 미치지 못한다는 것이 전제다. 그러나 **완화 대상을 잘못 고르면 보여줄 것이 사라진다.**

| 손대지 않는다 | 손댄다 |
|---|---|
| **패링 판정 창 0.32초** — 팀장 핵심 기술이자 포트폴리오의 전시물. 0.6초로 늘리면 "쉬운 게임"이 아니라 **"패링이 밋밋한 게임"**이 된다 | 패링 실패 후딜 0.35초 |
| **패턴 windup 1.2 / 1.5 / 2.0 / 0.8초** — [9.5](../02-game-design.md)의 학습 전이가 여기 걸려 있다 | 패턴 **피해량** |
| 3인 동시 기믹의 구조 | 기믹 **실패 시 즉시 전멸 아님** — 재시도 허용 |
| **전원 다운은 실패다** (2026-09-06 확정) — 개활맵, 보스맵, 트라이 모드가 전부 같다. 셋이 다 쓰러지면 남아 있던 자동 부활 타이머를 버리고 그 판을 끝낸다 | — |

> 위 표의 *"기믹 실패 시 즉시 전멸 아님"*은 **기믹 하나를 놓쳤을 때**의 이야기이지 전원이 쓰러진 상태가 아니다.
> 트라이 모드의 완화는 **다시 시도할 기회를 주는 것**이지 쓰러진 파티를 계속 굴리는 것이 아니다 —
> 재시도는 판이 끝난 다음에 온다.

> 🔒 **"성공하기 쉽다"가 아니라 "실패해도 안 죽는다"로 간다.**
> 실력이 낮은 플레이어에게 필요한 것은 관대한 판정이 아니라 **여러 번 시도할 기회**다.

이는 [9.2 즉사 패턴 금지](../02-game-design.md)와 같은 논리이며, **트라이 모드 자체가 가장 강력한 난이도 완화**다 — 실패해도 30분을 다시 걷지 않는다.

또한 [보스 연출 2.2](BOSS_STAGING_DESIGN.md)의 **컷신 스킵이 필수 조건이 된다.** 반복 도전에서 같은 8초를 수십 번 보게 된다.

## 7. 해금 조건

| 안 | 조건 | 판정 |
|---|---|---|
| A | 보스를 본 적 있음 | 기각 — 3인 중 누구 기준인지 정할 수 없고, 심사자는 항상 처음이다 |
| B | 항상 열려 있음 | 기각 — 30분 콘텐츠를 아무도 보지 않게 된다 |
| **C** | **런을 한 번이라도 시작한 적 있음** + **실행 인자 `-bosstrial`로 무조건 개방** | **채택** |

- `PlayerPrefs` **키 하나**로 충분하다. 3분이면 충족된다
- 전시·심사 상황은 실행 인자 `-bosstrial`을 사용한다. `BossTrialDirector`와 실행 인자 처리 코드를 기준으로 확인한다.

> ⚠️ **이것이 이 프로젝트 최초의 영속 데이터다.**
> `bool` 하나 수준이라 마이그레이션 문제는 실질적으로 발생하지 않으나, CLAUDE.md의 "세이브 데이터는 없다"는 전제가 엄밀히는 깨진다. 확장 요구가 올라오면 이 문단을 근거로 범위를 지킨다.

## 7.1 구현 상태 (2026-09-18)

서버 흐름은 구현했다. 화면과 씬 배치가 남았다.

| 항목 | 상태 |
|---|---|
| 편성 데이터 `BossTrialLoadoutSO` | **구현.** 시작 레벨 10, 편성 포인트 상한, 장비 필드 레벨별 비용, 물약 비용과 상한, 시작 재화. 실측 전 임시값이고 `Assets/09.Data/BossTrial/`에 있다 |
| 편성 예산 판정 | **구현.** `BossTrialRules.Validate`가 비용 합, 카탈로그 밖 등급, 물약 상한을 막는다. 서버와 화면이 같은 규칙을 본다 |
| 전실 수집 | **구현.** `BossTrialDirector`가 제출을 모으고, 다 모이기 전에는 `IBossTrialGate`로 보스 개시를 막는다. 60초가 지나면 남은 사람은 빈 편성으로 연다 |
| 편성 적용 | **구현.** 시작 레벨(경험치 일괄 지급), 시작 재화, 고른 장비 생성과 장착, 물약 지급 |
| 로비에서 직행 | **구현.** 트라이 런은 필드 시계를 돌리지 않고 시작 즉시 전실로 간다 |
| 재시도 | **구현.** 호스트 요청으로 로비를 거쳐 새 런을 다시 시작한다. 새 런이므로 보스, 부위, 표식, 시계가 전부 초기화된다 |
| 리더보드 미등록 | **이미 있음.** `RunResultSnapshot.IsLeaderboardEligible`이 정식 런만 통과시킨다 |
| 해금 | **구현.** `BossTrialUnlock` - 런을 한 번 시작하면 PlayerPrefs로 열리고 `-bosstrial` 인자로 무조건 열린다 |
| 설정 씬 `Dev_BossTrial` | **구현(개발용).** 레벨, 무기, 장비 등급 · 공격력 · 옵션 2칸, 특성 노드, 물약을 손으로 정하고 거기서 바로 시작한다. Boot 씬을 복사한 것이라 부트 경로가 그대로 있고, 설정 오브젝트는 씬 전환에도 살아남아 편성을 낸다 |
| 편성 적용 시점 | **보스 구간 진입 후.** 씬 전환이 참가자 상태를 다시 부으므로 그전에 주면 사라진다 |
| 무기 지정 | **로비 선호 경로를 쓴다.** 런이 시작된 뒤에는 이미 배분된 무기라 바꿀 수 없어, 준비를 누르기 전에 선호를 보내 그 무기로 확정시킨다 |
| **정식 편성 UI 패널** | **남음.** @kjw1237. 서버 창구는 `BossTrialDirector`의 Command와 SyncVar다 |
| **전실 공간 배치** | **남음.** `Boss_Arena.unity` 안 Antechamber |
| 검증 | L1 통과. L2, L3 미실행 |

## 8. 구현 순서

```
1. Antechamber 루트 (Boss_Arena 안)         ← 정식 런 경로부터. 3인 도착 확인
2. 로비 → Boss_Arena 직행 경로               ← 게이트 경로와 같은 진입 계약을 쓴다
3. BossTrialLoadoutSO (임시값)
4. 편성 UI 패널
5. 정산 분기 — 리더보드 등록 차단 + "연습 기록" 표시
6. PlayerPrefs 해금 + -bosstrial 인자
```

**1번부터 하는 이유** — 전실은 정식 런에도 필요하므로 트라이 모드가 취소되어도 버려지지 않는다.

## 9. ⚠️ 구조 변경 인지 사항

CLAUDE.md상 팀장 요청이어도 알려야 하는 항목이다. 막지 않는다.

- **`Boss_Arena.unity` 진입 경로가 둘이 된다** (게이트 통과 / 로비 직행). [8.2](../class-identity-and-boss-2026-09-03.md)의 매니저 다섯 영속화 계약이 **두 경로 모두에서** 성립해야 한다
- **영속 데이터가 프로젝트에 처음 생긴다** (7장)
- 씬 목록 자체는 바뀌지 않는다 — `Boss_Arena`는 이미 신설 예정이다
