# UI 기능 연결 · 아이템 획득 · 필요한 리소스

기준: 2026-09-20. 대상은 현재 개발 빌드의 `SessionManagers`에 연결된 관리 UI와 RunHUD다. `Dev_Title/Dev_Lobby` 전용 시안, 설정·제스처 아이콘은 이번 기능 연결 대상과 구분한다. 제작 전용 Dev 씬은 수정하지 않았다.

## 사용 흐름과 수정

| 기능 | 사용 방법 | 이번 연결/수정 |
|---|---|---|
| 배낭 | I → 칸 선택 | 서버 소유자 슬롯을 표시. 선택한 장비의 장착 버튼을 켜고 같은 자리에 겹친 해제 버튼을 숨김 |
| 장착·해제 | 장비 칸 → 장착, 선택 해제 상태에서 해제 | 기존 서버 revision/장비 조건 유지. 슬롯 재클릭도 기존 주동작을 실행함 |
| 특성 | 특성 탭 → 포인트가 있는 노드 → 초기화 | 탭 문구도 클릭되도록 수정. 포인트/선행 조건에 따른 비활성은 정상 동작 |
| 양도 | 배낭 장비 선택 → 양도 탭 → 동료 → 상대 수락 | 기존 서버 제안/수락/거절/취소 API 사용. 장착한 장비는 먼저 해제해야 함 |
| 물약·티켓 | 물약 선택 → 사용 / 장비 대상과 티켓 선택 → 티켓 사용 | 기존 서버 거래 결과를 배낭 상태 메시지로 표시 |
| 객주 | 2차 축소 중 객주 가까이에서 G | 거래는 서버가 승인해야 열림. 일반 배낭에서 항상 구매하는 기능은 아님 |
| 봇 배낭 | 배낭 → 동료 봇 배낭 | 이전 작업의 봇별 장비·12슬롯 조회 유지 |
| 지도 | M 확대/축소, Escape 접기 | 존재하던 MinimapExpandToggle을 실제 RunHUD에 연결. 확대 배경 추가 |
| 페이지 제목 | 탭 전환 | 배낭/특성/양도/객주를 현재 페이지에 맞춰 표시 |
| 아이템 줍기 | 근처에서 [G] 등급·무기 줍기 → I | 후보 안내와 서버 획득/거절 결과를 새 InteractionPromptView에 연결 |

## 몬스터 → 드롭 → 배낭

`EnemyStatus` 실제 사망 → `EnemyDiedEvent` → `DropDirector` → `DroppedItem` 서버 스폰 → 소유 플레이어의 `InteractionController` Command → 서버 거리·생존·전투·런/씬 검사 → 예약 → `InventoryController.ServerTryStoreEquipment` → 성공한 경우만 바닥 객체 제거 → 소유자 슬롯 동기화 순서다.

- 일반 몬스터 장비 드롭 확률은 `Assets/09.Data/DropTable/DropTableSO.asset`의 15%다. 모든 몬스터가 반드시 떨어뜨리지는 않는다. 이번 작업에서 확률은 바꾸지 않았다.
- 줍기는 접촉 자동 획득이 아니라 **G 상호작용**이다. 현재 드롭 종류는 장비(검/활/방울)이고 물약/티켓은 객주에서 구매한다.
- 전투 후 비전투 대기 및 거리 수치는 Combat SO가 정한다. 실패하면 전투 중/거리/배낭 공간 등 사유를 표시한다.
- 서버는 가득 찬 배낭에 넣지 못한 원본 아이템을 유지한다. 런 정지·씬 전환 중 또는 다른 씬 대상 요청도 거절하도록 보완했다.
- 획득 데이터는 생성된 장비 인스턴스 ID로 추적한다. 화면만 바뀐 것으로 성공 판정하지 않는다.

## 제작·연결이 필요한 리소스

아래 규격은 제작 권장안이며 기능 실행을 막는 필수 조건은 아니다. 현재는 문자·기존 UI·큐브 대체물로 동작한다. 기존 외부 에셋을 재사용할 때는 프로젝트 배포 권한과 원본 경로를 함께 기록한다.

| 우선순위 | 리소스 | 수량/권장 규격 | 적용 위치·완료 조건 |
|---|---|---|---|
| P1 | 바닥 장비 모델 또는 식별 가능한 드롭 꾸러미 | 검/활/방울 3종 또는 공용1종+3표식, FBX/prefab, URP 재질 | DroppedItem의 Visual 자식 교체. NetworkIdentity·콜라이더·스크립트는 보존, 바닥에 묻히지 않고 원거리에서 구분 |
| P1 | 인벤토리 물품 아이콘 | 검/활/방울/체력물약/신력물약/재조정권/승급권 총7종. 기존3개 재활용 가능. 투명 PNG 128~256px 원본 | 슬롯·상점·봇 배낭에서 동일 매핑. 체력/신력, 재조정/승급이 서로 구분되어야 함 |
| P1 | 등급 표시 | 일반/부적/영험/신물 4종 테두리 또는 공용틀+4색 | 월드 표식과 슬롯에 같은 규칙 적용. 색만 의존하지 않고 등급명 유지 |

## 검증 상태

2026-09-20 당시 같은 PC 호스트+참가자 2명 M2에서 몬스터 사망→드롭→G 획득→요청자 배낭 저장과 복제를 확인했다. 장착·해제, 특성, 양도, 물약, 권, 객주, 지도와 가득 찬 배낭의 실패 보존도 확인했다.

당시 빌드 결과는 현재 변경의 검증을 대신하지 않는다. 자체 계정 릴레이의 외부 PC 3인, Steam 호환 회귀, 장시간 자연 플레이는 별도 확인한다. 신규 특성 UI 계약은 [담당자 인계](TALENT_UI_HANDOVER.md)를 따른다.
