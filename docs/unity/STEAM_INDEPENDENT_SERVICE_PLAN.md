# 자체 계정·런처·리슨 서버 운영 구조

2026-09-22 코드 기준. 과거의 ASP.NET·RDS 필수·방별 Unity 전용 서버 권장안은 현재 운영안이 아니다.

## 1. 현재 구성

| 구성 | 책임 | 코드 |
|---|---|---|
| WPF 런처 | 로그인·자동 로그인·게임 설치/업데이트·방 목록·파티 편성·봇·준비·출발 | `launcher/Launcher.UI/`, `launcher/Account.Client/` |
| Python FastAPI | 계정·세션·방/멤버·접속 티켓·릴레이 자격증명·공지 대기열 | `backend/src/geumeum_backend/` |
| Python Discord 봇 | 공식 서버에서 계정 관리용 일회 링크 발급, 승인된 공지 작업 처리 | `discord_bot.py`, `discord_web.py` |
| PostgreSQL | 계정·세션·Discord 연결·방·공지 상태 | SQLAlchemy models와 Alembic migrations |
| Unity 방장 | Mirror StartHost, 이동·전투·경제·런 판정 | `AccountGameServer`, `GeumeumNetworkManager` |
| AWS UDP 릴레이 | 일반 사용자의 공유기 설정 없이 게임 패킷 전달 | `relay.py`, `AccountRelayTransport` |
| R2 패치 저장소 | 서명된 게임/런처 파일 배포 | `launcher/scripts/sync-server.ps1` |

운영은 기존 EC2에서 API·봇·DB·릴레이를 함께 실행한다. 방마다 AWS 게임 서버를 띄우지 않는다. `game_worker.py` 등 전용 서버 코드는 남아 있지만 현재 리슨 운영 경로와 구분한다. 개인 계정의 크레딧·잔액·인스턴스 식별자는 팀 공용 계약이 아니다.

## 2. 사용자 흐름

1. [공식 Discord 서버](https://discord.gg/8tzFAqQNvc)에 참여해 `/계정` 명령을 실행한다. 개인 응답의 `계정 설정 열기`에서 아이디·비밀번호·닉네임을 설정한다. 채팅에 비밀번호를 입력시키지 않는다.
2. 런처에서 로그인한다. 비로그인 시 게임 시작을 허용하지 않는다.
3. 방 목록을 수동 새로고침해 생성/참가한다. 생성자가 방장이다. 참가 중에도 다른 방 목록을 볼 수 있다.
4. 파티에서 무기·봇·준비를 설정하고 방장이 출발한다. 게임 실행은 전투를 시작하기 위한 단계다.
5. 방장은 리슨 서버를 시작하고 참가자는 HTTPS 권한 확인 및 일회 접속 티켓을 거쳐 릴레이로 접속한다.

방 목록 자동 반복 조회는 제거됐지만, 참가 중 파티 임대 갱신과 출발 신호 수신은 계속 필요하다. 이를 방 목록 새로고침과 혼동해 제거하지 않는다.

## 3. 계정·인증 계약

- 신규/변경 비밀번호는 Unicode code point 8~15자. 로그인과 현재 비밀번호 입력은 기존 계정 호환을 위해1~128자.
- 아이디는 ASCII 소문자/숫자/밑줄4~24자 정규화, 닉네임은 NFC 정규화 후2~16자 및 금지 문자 검사. 정확한 검증 원본은 `schemas.py`다.
- Argon2id 해시와 접근/갱신 토큰을 사용한다. 토큰 원문 대신 해시를 저장하고 갱신 토큰 회전·재사용 차단을 적용한다.
- 비밀번호 변경은 기존 세션을 폐기한다. 런처 저장은 Windows DPAPI. 게임에는 수명이 제한된 별도 게임 세션을 전달한다.
- 공개 가입/연결 작업은 Discord에서 발급한 제한된 일회 티켓으로 보호한다. 운영자용 테스트 계정 생성 CLI와 일반 사용자 가입을 구분한다.
- 스키마/API 오류에 비밀번호 원문을 포함하지 않는다. 환경 파일·봇 토큰·서명 개인키는 버전 관리하지 않는다.

## 4. 게임 서버와 API의 경계

FastAPI는 방/로그인만이 아니라 접속 인증과 게임 패킷 중계도 담당한다. 전투 시뮬레이션은 방장 PC에 있다. 호스트 권위의 한계나 서버 상태를 클라이언트 UI에서 직접 변경하지 않는다.

[릴레이 계약](ACCOUNT_RELAY.md)에 암호화·MTU·재전송 방어·폐기·제한이 있다. API와 릴레이는 같은 프로세스이므로 API 재시작 때 진행 게임이 끊긴다. 자동 호스트 이전과 UDP 차단 회선 대체 전송은 아직 없다.

## 5. 로컬 실행과 운영 배포

- 로컬 개발: [백엔드 README](../../backend/README.md), [로컬 플레이](../../backend/README.md), [런처 계정 실행](../../launcher/ACCOUNT_LOCAL.md).
- 운영 설치: [AWS 배포 절차](../../backend/deploy/aws/README.md). 현재 환경값은 예제와 실제 배포 설정을 구분한다.
- 게임 배포: [패치 시스템](PATCH_SYSTEM_DESIGN.md). 원격 게임 releaseId와 API `GEUMEUM_GAME_BUILD_ID`를 맞춘다. 런처만 배포하면 게임 허용 빌드는 바꾸지 않는다.
- 공지는 대기열·발송 구현이 있다는 사실과 실제 발송 승인을 구분한다. 배포만 요청했다고 자동으로 Discord 메시지를 발송하지 않는다.

## 6. 검증과 후속

계정/방 Python 통합 테스트, 런처 계정/WPF 테스트 및 AWS 경유 호스트+2참가자/봇 시나리오 기록이 있다. 이는 외부 회선 PC3대·장시간 부하·모든 전투 조합 검증을 대신하지 않는다. 재현 방법은 위 실행 안내와 [멀티플레이 절차](../ai/04_MULTIPLAYER_TEST_PROTOCOL.md)를 따른다.

추가 운영 과제는 진행 방을 보존하는 배포 구조, 실제 방별 전송량 측정, 서버 밖 백업 및 실회선 검증이다. 개인 비용 견적을 측정된 한 판 원가로 단정하지 않는다.
