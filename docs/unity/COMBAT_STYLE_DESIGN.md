# 액티브·스타일 전투 표현 설계 — 젠레스 존 제로·마비노기 영웅전 참고

> 작성·개정: 2026-09-24 · 상태: **1차 구현됨(미검증)** — 피해 결과 계약, S1~S7·S9·S10 일부 코드 반영. 3인 테스트(L3)·체감 검증 전. 항목별 현황은 [14장](#14-구현-현황-2026-09-24) · 요청: 팀장
> 개정 범위: 코드 대조에서 확인한 결과 전달·패링 시각 계약 보정, 데미지 숫자(S10) 설계 추가. 숫자 표시의 세부 값은 아래 제안 기본값이며 체감 검증 전이다.
> 관계: [전투 감각·보스 방향 검토](COMBAT_FEEL_AND_BOSS_DIRECTION.md)의 **C안 위에 얹는 표현 층**이다. C안의 규칙(공격 핵심 구간 취소 불가, 자유 이동 평타 없음, 입력 예약 한 칸, 일반 피격 C1)은 바꾸지 않는다.
> 카메라 기반: [카메라와 락온](CAMERA_AND_LOCKON.md) 0·6·6.1장 — Cinemachine 전환, 프레임 독립 셰이크, 카메라 연출(2026-09-24 구현).
> 참고작 서술은 플레이 경험과 공개 영상에 근거한 **해석**이다. 원작의 프레임 수치를 측정하거나 추출한 값이 아니며, 아래 숫자는 전부 그믐의 제안 시작값이다.

## 1. 결론

**기존 공방 규칙을 유지하면서 타격의 강약과 실제 피해 결과를 분명하게 만든다.** 데미지 숫자와 결과 전달은 신규 기능이며, 극한 회피는 표현 외에 신규 서버 판정도 필요하다.

그믐에는 패링·구르기 무적·3연격·적 경직/넉백·히트스톱·스킬·공동 그로기가 이미 있다. 참고작이 스타일리시하게 느껴지는 이유는 기능 수보다 두 가지다.

| 원리 | 뜻 | 그믐에서 할 일 |
|---|---|---|
| **때린 순간이 무겁다** (마비노기 영웅전) | 때린 쪽과 맞은 쪽이 같이 멈추고, 무기·타격마다 무게가 다르다 | 적도 멈추는 히트스톱, 타격 강도 사다리(5장) |
| **대응한 순간에 보상이 확실하다** (젠레스 존 제로) | 적 공격 직전 섬광 → 막거나 피하면 화면·소리·반격이 한 번에 터진다 | 타이밍 섬광(S4), 극한 회피(S7), 그로기 진입 공동 연출(S9) |

우선순위는 **현재 카메라의 3인 기준선 → 결과 전달 계약 → 검·잡귀 한 종류의 S1/S2/S5 및 S10 → S4/S9** 순이다. 표현은 클라이언트에서 재생하지만 필요한 서버 결과가 이미 전달된다는 뜻은 아니다. 효과의 크기는 실제 조작 비교로 검증한다. 보스 공격 중 히트스톱과 S7은 후순위다.

## 2. 기존 결정과의 관계

### 2.1 그대로 지키는 것

| 기존 결정 | 출처 | 이 문서에서의 의미 |
|---|---|---|
| 공격 핵심 구간은 취소하지 않는다. 입력 예약은 한 칸 | [전투 방향 1장·10.1](COMBAT_FEEL_AND_BOSS_DIRECTION.md), [전투 개편 4장](PLAYER_COMBAT_REWORK.md) | 젠존제식 "아무 때나 회피 캔슬"은 가져오지 않는다. 회피→공격 연결은 기존 예약(C3)으로 만든다 |
| 공격 모션과 무관하게 끌려가는 이동은 싫다 | 전투 방향 머리말(사용자 제약) | 돌진·흡착 공격을 넣지 않는다 |
| 적 시각 반응과 실제 경직을 나눈다. 보스는 평타마다 전신을 멈추지 않는다 | 전투 방향 7.2 | 적 히트스톱(S1)은 표현이고 보스에는 약하게만 건다 |
| 큰 순간을 위해 평소 강도를 남긴다. 동료 평타가 내 화면을 흔들지 않는다 | 전투 방향 7.4 | 5장의 강도 사다리가 이 규칙을 수치로 옮긴 것이다 |
| 카운터 가능 여부를 색 하나에만 맡기지 않는다 | 전투 방향 7.4 | 섬광(S4)은 색 + 모양 + 소리 세 겹이다 |
| 패링 창은 현재 공격 대상 1인에게만 열린다 | [전투 개편 5장](PLAYER_COMBAT_REWORK.md) | 섬광은 대상에게 강하게, 나머지에게 약하게 |
| 패링 0.32초 판단을 방해하는 지속 화각 변화·과한 흔들림 금지 | [카메라 2.3](CAMERA_AND_LOCKON.md) | 화각 펀치는 순간만, 합산 상한 유지 |
| 보스 패턴 QTE 없음 | [보스 패턴 계약 1장](BOSS_PATTERN_CONTRACT.md) | 그로기 연출은 입력을 잠그지 않는다 |

### 2.2 이 문서가 새로 다루는 것

1. **타격 강도 사다리** — 모든 타격 표현(히트스톱·셰이크·화각·섬광·소리)을 여섯 단계로 묶는 데이터 규칙
2. **적 쪽 표현** — 적 히트스톱, 방향 있는 움찔, 처치 강조
3. **타이밍 섬광** — 패링 창이 열리는 순간을 알리는 신호
4. **극한 회피** — 구르기 무적으로 공격을 흘린 순간의 표현(보상은 별도 결정)
5. **공동 순간** — 그로기 진입·꼬리 파괴를 셋이 동시에 느끼는 연출
6. **데미지 숫자** — 내가 준 실제 피해와 치명타를 적중 위치에서 확인하는 로컬 UI(S10)

## 5. 핵심 구조 — 타격 강도 사다리

**타격 표현은 여섯 단계의 기본 프로필을 사용한다.** 단계는 표현의 중요도이며 피해 배율이 아니다. 채널별 비활성·상한·무기 예외를 허용한다. 숫자의 값과 치명 여부는 서버 결과로 정하고 T 단계에서 역산하지 않는다.

| 단계 | 해당 순간 | 공격자 멈춤 | 대상 멈춤 | 셰이크 | 화각 | 화면 플래시 | 소리 층 | 보는 사람 |
|---|---|--:|--:|---|--:|---|---|---|
| **T0** | 헛스윙 | 0 | 0 | 없음 | 0 | 없음 | 바람 | 나 |
| **T1** | 평타 1·2타 적중, 화살 적중, 방울 적중 | 0.04 | 0.04 | 약 (0.07m) | −0.6° | 없음 | 접촉 | 나 |
| **T2** | 3타 마무리, 무기 스킬 적중, 찌르기, 표식 1개 받아베기 | 0.06 | 0.06 | 중 (0.12m) | −1.2° | 없음 | 접촉 + 저음 | 나 |
| **T3** | 치명타, 패링 성공, 표식 2~3개 받아베기, 정밀 사격 명중, 잔향 폭발 | 0.08 ¹ | 0.08 (보스 0.03 ²) | 강 (0.15~0.20m) | −1.5~−2° | 0.06초 약 | 접촉 + 저음 + 고음 반짝 | 나 |
| **T4** | 잡귀 처치(마지막 일격) | 0.10 | 0.10 | 강 | −1.5° | 0.06초 약 | 처치음 | 나 |
| **T5** | 그로기 진입, 꼬리 파괴 | 없음 | 보스 자세 전환 | 최강 (0.25~0.30m) | ±1.5~2.5° | 0.10초 | 파티 공통 효과음 | **파티 전원** |

- ¹ 패링 성공은 T3이어도 공격자·대상 멈춤을 자동 적용하지 않는다(5.1). ² 보스 대상 멈춤은 첫 도입에서 끄고, 예고·공격 중이 아닐 때만 비교한다(S1).
- **공격자 멈춤·대상 멈춤은 각자 자기 화면에서만** 재생한다. 서버 시계와 다른 플레이어의 조작을 멈추지 않는다([전투 방향 10.2](COMBAT_FEEL_AND_BOSS_DIRECTION.md)).
- **남의 타격은 T0~T4 모두 셰이크·화각·플래시 없음.** VFX와 소리만, 소리는 `SFX_Remote` 그룹으로 낮춘다.
- **신궁의 원거리 공격은 공격자 멈춤을 쓰지 않는다.** 공통 `CombatFeedbackImpl`의 활 제외와 별개로, 근접 R 찌르기는 `PlayerCombatPresentation.abilities`에 0.03초 멈춤 경로가 있다. 이 근접 예외를 유지해 비교하며 직업 전체를 일괄 0으로 만들지 않는다.
- 표의 멈춤·셰이크 값은 시작값이다. 현재 적용된 값과 다른 칸(T2 0.06, T4 0.10 등)은 이 문서를 채택할 때 바뀌는 값이다.

### 5.1 중첩과 예외

- 같은 타격의 3타·치명·처치는 가장 높은 T 단계 하나를 선택한다. 치명 표시는 처치로 승격되어도 보존한다. 한 공격이 여러 적을 맞혀도 공격자 멈춤·카메라 효과는 공격 단위 한 번만 재생한다.
- T5와 개인 타격이 겹치면 카메라·플래시는 T5를 우선하며 더하지 않는다. 현재 `CameraConfigSO` 합산 상한을 유지하고 전역 표현 배수·플래시 끄기를 제공한다.
- 대상 멈춤은 같은 대상의 종료 시각을 무한 연장하지 않는다. 첫 요청부터 최대 0.10초, 종료 후 0.10초 재발동 유예를 제안한다. 사망·그로기·새 공격 예고가 시작되면 복원하고 우선 상태로 전환한다.
- 패링 성공 T3는 기본적으로 소리·카메라의 중요도다. 공격자/대상 멈춤을 자동 적용하지 않는다. 보스 T1~T2 대상 멈춤은 0이며 T3 이상도 S1 제한을 따른다.
- 숫자는 대상별 피해 사실을 모두 처리한다. 카메라 효과의 공격 단위 병합 때문에 피해 숫자가 누락되어서는 안 된다.

## 6. 항목별 설계

각 항목에 **권위**(서버 판정인지, 각자 화면 표현인지)와 **검증 수준**을 적는다. 표현 항목도 네트워크 결과를 받아 재생하므로 L3 확인이 필요하다.

### S1. 대상 히트스톱 — 적도 같이 멈춘다

| | |
|---|---|
| 목표 | 내 타격이 적에게 "걸리는" 감각. 마비노기 영웅전의 핵심 |

### S4. 타이밍 섬광 — "언제"를 알린다 (젠레스 존 제로)

| | |
|---|---|
| 목표 | 바닥 데칼은 "어디서"를 알려 준다. 섬광은 **패링 창이 열리는 순간**을 알려 준다 |
| 시점 | 실제 `ParryController`는 `windowEnd = impact − PARRY_RESOLUTION_LEAD`, `windowStart = windowEnd − Clamp(공격별 창 길이 + loadout.ParryWindowBonus)`를 쓴다. Clamp 범위도 같은 서버 코드를 따른다. **대상에게 보낸 확정 시작·종료 시각**을 사용하고 0.32초를 상수로 역산하지 않는다 |
| 모양 | 패링 가능: 무기 끝에 **짧은 한 번의 반짝**(데칼과 같은 파랑 계열) + 맑은 고음 · 패링 불가: 무기 전체에 **두 번 번지는 붉은 빛** + 낮은 경고음. 색·모양·소리 세 겹이라 색각 차이에도 구분된다 |
| 대상 구분 | 패링 창은 공격 대상 1인에게만 열린다. **대상은 강하게, 나머지는 약하게**(크기·음량 절반) 본다. 나머지도 피해야 하므로 끄지는 않는다 |
| 권위 | 대상은 기존 `TargetOpenParryWindow(key, start, end)`를 표현 이벤트로 노출해 사용한다. 비대상에게 동일한 창 시작을 보여주려면 cue 확장이 필요하다. `PatternId/RepeatIndex`만으로 대상의 장비 보정까지 복원할 수 없다 |
| 접점 | 보스 cue의 공격/반복/대상 키와 패링 window key의 연결을 정의한다. 잡귀는 `EnemyParryWindowFlash`를 통합하고 TintRegistry를 유지한다. **Telegraph 진입 자체를 창 시작으로 쓰지 않는다** |
| 위험 | 엇박 패턴에서 섬광이 판정과 어긋나면 오히려 패링을 망친다 → 섬광은 **실제 창 시작 시각**에 맞추고, 엇박 지연은 섬광도 같이 늦춘다(보스 계약 10장) |
| 검증 | L3 필수. RTT 0/80/150ms에서 섬광과 실제 창 차이 측정 |

패링 불가 공격에는 패링 창이 없다. 해당 경고는 서버 impact와 패턴별 경고 선행시간으로 예약하고, 패링 가능 신호와 의미를 구분한다. 취소/개정/반복 키로 중복을 제거한다. 늦게 받은 창이 아직 열려 있으면 남은 구간 강조만 하고 과거 시작 섬광을 새로 재생하지 않는다. 닫힌 창은 표시하지 않는다. 비대상 약한 신호도 자신의 패링 가능 표시로 오해되지 않게 구분한다.

### S7. 극한 회피 (젠레스 존 제로) — **팀 결정 필요**

| | |
|---|---|
| 목표 | 구르기가 "도망"이 아니라 "기회의 시작"으로 느껴지게 |
| 판정 | **서버**: 구르기 무적 0.45초 중 **앞 0.15초** 안에 무적 때문에 무효가 된 타격이 있으면 극한 회피. 서버가 회피자에게만 결과를 보낸다 |
| 1단계 — 보상 없음 | 0.3초 화면 가장자리 어둡게 + 잔상 + 고음 반짝. 적 공격 중 대상 히트스톱은 제외한다. 단색 UI 오버레이는 실제 월드 채도 감소가 아니므로 그렇게 표기하지 않는다. **전역 슬로우모션 없음**(7장) |
| 2단계 — 보상 (선택) | 후보: 구르기 스태미나 환급. **공격력 증가·반격 표식은 주지 않는다** — 차사의 패링→받아베기 정체성과 겹치고, 모든 직업이 회피만 노리는 최적해가 생긴다 |
| 위험 | 지연 공정성 — 판정이 서버 시각이라 RTT가 크면 극한 회피가 덜 나온다. 기존 패링 지연 보정처럼 클라이언트 주장 시각을 그대로 믿지 않는다 |
| 결정 | ① 1단계만 할지 ② 2단계 보상까지 할지. 권장: **1단계만 먼저**, C4(보스 한 패턴 공방) 측정 뒤 2단계 판단 |
| 검증 | L3, RTT 0/80/150ms에서 발생률 비교 |

보상을 주지 않아도 극한 회피 성공을 판단하는 서버 로직은 신규다. 현재 `PlayerStatus`의 공용 무적 bool만으로는 원인을 구별할 수 없다. 구르기 실행 ID·서버 무적 시작 시각·무적 원인과 적 공격 실행/반복 ID를 연결하고, 양의 유효 공격이 충돌했으나 구르기 무적으로 거부된 경우만 인정한다. 부활·패링·개발 무적·환경 피해는 제외한다. 한 구르기당 성공 연출 1회를 상한으로 하고 같은 공격의 다중 콜라이더도 중복 제거한다. `DamageInfo` 등 공용 계약 확장 범위와 원인별 우선순위는 구현 전에 확정한다.

### S10. 데미지 숫자 — 내가 준 피해를 읽는다

**적중한 적 근처에 내가 실제로 준 피해를 표시한다.** 숫자는 판정의 결과이며 타격감의 유일한 신호가 아니다. 보스의 몸·공격 예고·조준점을 가리지 않는 것을 우선한다. 아래는 제안 기본값이다.

| 항목 | 규칙 |
|---|---|
| 표시 범위 | 기본 **내 피해만 ON**, 끄기 제공. 동료 피해·DPS 순위·누적 딜 미터·회복 숫자·플레이어 피격 숫자는 이번 범위 밖. 그로기/꼬리 공동 연출은 숫자 설정과 무관하게 유지 |
| 값 | 서버가 확정한 **실제 HP 감소량**. 방어/피해 배율/무적/HP 게이트 적용 후, 남은 HP를 넘는 초과 피해 제외. 클라이언트 공격력 계산이나 체력 SyncVar 차분으로 만들지 않는다 |
| 0 피해 | 무적·잠긴 부위·빗나감은 피해 숫자를 띄우지 않는다. 무효 이유 문구는 별도 후속 UI이며 0을 적중처럼 반복 표시하지 않는다 |
| 숫자 형식 | 양의 값은 정수 반올림(0.5 이상 올림), 1 미만은 `<1`. 천 단위 쉼표 사용, 초기 버전은 K/M 축약 없음. 표시 반올림으로 서버 피해값을 바꾸지 않는다 |
| 일반/치명 | 일반은 따뜻한 흰색, 치명은 금색 + 작은 치명 표식 + 크기 1.2배. 색만으로 구별하지 않는다. T3 패링·스킬이라는 이유만으로 치명 표시하지 않는다 |
| 강도 연계 | T1 기본, T2~T4 진입 크기 최대 1.2배. 치명 배수와 곱하지 않고 큰 쪽 하나만 사용. T5는 별도 공동 연출이며 피해 사실이 없으면 숫자를 만들지 않는다 |
| 위치 | 서버 확정 적중점에서 화면 좌표로 투영, 짧게 위로 이동. 생성 이후 적의 뼈/현재 위치를 계속 추적하지 않는다. 본체·꼬리·원혼은 맞은 대상/부위의 위치를 사용 |
| 가독성 | 1080p 기준 기본 24px·수명 0.65초를 시작값으로 비교. 검은 외곽선, 작은 좌우 분산, 조준점·패링 신호 보호 영역과 HUD를 피해 배치. 해상도/UI 배율 대응, 텍스트 raycast OFF |
| 시야 밖 | 카메라 뒤·화면 밖·지형에 가린 적중점에는 새 숫자를 만들지 않는다. 화면 가장자리에 몰아 붙이지 않는다. 사망으로 대상이 사라져도 저장된 적중점으로 남은 수명만 표시 |
| 밀도 | 화면 동시 최대 24개, 같은 대상 최대 4개부터 비교. 초과 시 일반 숫자부터 병합/교체하고 치명도 전체 상한은 넘지 않는다. 상한 때문에 원본 피해 사실이나 전투 결과를 버리지 않는다 |
| 성능 | 재사용 풀과 고정 크기 대기 버퍼 사용. 숫자마다 NetworkObject 생성 금지. 가림 검사는 생성 시 유한 예산으로 수행하며 대상별 결과를 짧게 재사용. 폰트/재질 공유, 프레임별 문자열 재생성 금지 |

**합산 규칙:** 최초 피해는 즉시 표시한다. 0.08초 이내에 같은 공격자·공격 실행·대상(부위 포함)·피해 종류·치명 여부로 들어오는 후속 피해만 기존 숫자에 더한다. 서로 다른 평타/연격 실행, 본체와 꼬리, 일반과 치명은 합치지 않는다. 합산은 반올림 전 실제 피해량으로 수행하고 최종 표시에서 반올림한다. 갱신으로 수명을 무한 연장하지 않는다. 밀도 상한의 병합도 같은 키에만 허용하며 불가능하면 오래된 일반 숫자를 교체한다. 이것은 표시 축약이지 서버 피해 집계 변경이 아니다.

**공격 경로:** 검·활·방울 평타, R, 정밀 사격, 쐐기/잔향 등 파생 피해까지 결과 발생 지점을 목록으로 관리한다. 하나의 피해를 공격 코드와 피격 코드에서 두 번 발행하지 않는다. 소유자가 있는 파생 피해는 서버가 확정한 원 소유자에게 전달한다. 꼬리 피해와 본체 반영 피해가 같은 타격에서 함께 발생하면 중복 표시에 해당하는지 명시하고, 기본은 실제로 때린 부위의 피해 한 건을 표시한다. 별개의 실제 피해가 발생하는 공격만 별도 건으로 처리한다.

**접점:** 팀장은 실제 적용 피해 결과와 소유자 전달 계약, @kjw1237은 숫자 풀·배치·설정 UI, 아트는 폰트/치명 표식/이동 곡선을 맡는다. 새로운 숫자가 기존 `HealthDecreased` 플래시나 능력 VFX를 중복 발생시키지 않게 소비자를 분리한다.

## 8. 권위와 네트워크

| 내용 | 누가 정하나 | 전달 |
|---|---|---|
| 타격 확정·실제 피해·치명타·처치 | 서버 | **대상별 결과 계약 추가/확장**. 개인 숫자·멈춤은 공격자에게 전달 |
| 경직·넉백 | 서버 | 기존 상태 동기화 유지. T 단계로 판정을 새로 만들지 않음 |
| 극한 회피 판정 (S7) | 서버 | 원인/공격 식별 계약 + 회피자 전용 결과 전달 신규 |
| 패링 창 시각 | 서버 | 대상은 기존 TargetRpc 활용, 비대상 정확 시각은 cue 확장 필요 |
| 히트스톱·셰이크·화각·플래시·섬광·움찔·숫자 | 각자 화면 | 서버 결과를 소비. 효과의 프레임별 상태는 동기화하지 않음 |
| 그로기·꼬리 파괴 공동 연출 | 서버가 사건 확정, 표현은 각자 | 기존 호출 지점 |

**메시지가 S7 하나만 추가된다고 가정하지 않는다.** S1~S3/S10의 피해 결과와 S4의 비대상 시각 전달도 네트워크 작업이다. 기존 RPC 확장과 별도 결과 배치 중 선택은 발생 빈도·수신자·실측 대역폭으로 결정한다.

### 8.1 대상별 피해 결과 계약 — 신규 제안

현재 `RpcMeleeResult(executionId, didHit, wasCritical, impactGameplayTime)`에는 대상·피해량·처치가 없다. `RpcAbilityEvent(kind, point, count, time)`도 실제 피해 사실을 대체하지 않는다. `EnemyStatus.Damaged/Died`는 서버 이벤트이며 체력 SyncVar 훅에는 공격자 정보가 없다.

| 필드 의미 | 필요한 이유 |
|---|---|
| 세션/런 세대 + 서버 피해 사건 ID | 호스트 이중 실행·재수신 중복 제거, 이전 런 결과 폐기 |
| 공격자 식별 + 공격 실행/반복 ID + 피해 원인 | 소유자 전달, 다중 적중 카메라 병합, 파생 피해 구별 |
| 대상 netId + 대상 종류/부위 ID | 보스 본체·꼬리·원혼 구분. netId만으로 부위를 합치지 않음 |
| 실제 적용 피해량 + 치명 여부 + 처치 여부 | S10 값·스타일, S3. 대상 HP SyncVar 도착 순서에 의존하지 않음 |
| 적중 위치 + 방향 | S1/S2/S10. 디스폰 후에도 위치 기반 표현 가능 |
| 서버 게임 시각 + 행동 종류/콤보 단계/소비 표식 등 최소 메타데이터 | 늦은 결과 처리, T 단계의 일관된 로컬 선택. 최종 표현 수치 자체는 보내지 않음 |

피해 적용 계층에서 적용 전후 HP와 판정 결과를 확정한 직후 한 번 발행한다. 부위처럼 별도 피해 API가 적용량을 반환하는 경로도 같은 계약으로 정규화한다. 실제 변화가 없는 공격은 피해 결과를 만들지 않는다. 서버용 기록 인터페이스를 클라이언트 이벤트 버스로 간주하지 않는다.

개인 숫자·대상 멈춤은 소유 클라이언트에게만 전달하고, 동료에게 필요한 방향 움찔은 관찰자에게 최소 정보만 전달한다. 같은 사건이 두 경로로 와도 소비자별 사건 ID로 중복을 막는다. 호스트도 동일 수신 경로를 사용한다. 봇 피해를 관전자의 개인 피해로 자동 표시하지 않는다.

결과는 피해 처리 순서대로 신뢰성 있는 전달을 사용하되, 한 틱의 여러 건을 제한된 크기로 묶을 수 있다. 큐/배치 상한과 초과 처리, 수신 후 최대 재생 지연은 데이터/구현 계약으로 정한다. 게임 시각 기준 0.5초 이상 늦은 개인 표현은 폐기하는 시작값을 제안하고 누락 통계를 기록한다. 재접속에 과거 숫자를 재생하지 않으며 씬/런 변경 시 큐를 비운다. 대상이 사라지면 숫자·소리만 위치에서 재생하고 Animator 접근은 생략한다. 피해 자체는 어떤 표현 누락에도 영향을 받지 않는다.

### 14.3 데이터와 층

- 수치는 `PresentationConfigSO`의 `impact`, `damageNumbers` 부분(각 partial 파일)과 `CombatConfigSO._perfectDodgeWindowSeconds`에 있다. 에셋에 아직 저장하지 않은 새 필드는 코드의 초기값을 쓴다.
- 화면 층의 캔버스 정렬 순서: 화면 플래시, 먹 번짐, 가장자리 어둡게는 −20, 데미지 숫자는 −10, HUD는 0이다.
- 강도 사다리로 대체된 히트스톱 설정(`Light`, `Critical`, `SwordSkill`, `Bell`, `BellBurst`)은 지웠다. `BowStabHitStopSeconds`는 찌르기 근접 예외(5장)로 아직 쓴다.
- 새 소리 키 `ParryWindowFlash`(188), `UnparryableWarning`(189), `PerfectDodge`(190)는 기존 클립을 피치만 바꿔 **임시로** 연결했다. 전용 클립으로 바꾼다.

### 14.4 알려진 위험

- 근접 타격감이 이제 피해 결과 전달에 달려 있다. 원격 클라이언트는 결과가 RTT만큼 늦게 오므로, 멈춤과 셰이크도 그만큼 늦는다. RTT 150ms 체감은 L3에서 확인해야 한다.
- 보스 HP 하한이나 무적 구간처럼 실제 HP가 줄지 않는 적중은 결과가 없어 멈춤·셰이크가 나오지 않는다. 8.1 규칙대로지만 헛스윙처럼 느껴지는지 확인한다.
- 새 네트워크 경로: TargetRpc 두 종류(`TargetDamageResults`, `TargetPerfectDodge`)와 정리 RPC 하나, 비신뢰 ClientRpc 하나(`RpcObservedHit`). 대역폭은 아직 측정하지 않았다. 비신뢰 채널은 AccountRelay, KCP, FizzySteamworks 세 경로에서 각각 확인한다.
- 게임 폰트(`Hangeuljaemin4-Regular SDF`)는 Dynamic 아틀라스라 플레이할 때마다 글자가 에셋에 추가돼 변경으로 잡힌다. 이 기능만의 문제는 아니며, 커밋 전에 되돌리거나 정적 아틀라스로 굽는다.
