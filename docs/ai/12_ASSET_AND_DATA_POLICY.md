# 에셋 · 데이터 취급 정책

> 이 프로젝트에서 외부로 나가면 안 되는 것과, 라이선스를 지켜야 하는 것을 정한다.

---

## 1. 외부 AI에 넣어도 되는 것

| 등급 | 내용 |
|---|---|
| 문제없음 | 자신이 작성한 코드, 기획 문서, 공개 API 사용법, 일반 기술 질문 |
| 주의 | 팀원의 코드 (본인 확인 후), 미공개 기획 내용 |
| 금지 | 구매 에셋의 원본 코드 · 모델 · 텍스처, 계정 정보, API 키 |

---

## 2. 구매 에셋

**구매 에셋의 원본 파일을 외부 AI에 업로드하지 않는다.**

Gaia, Console Pro 3, Maintainer 2 등은 각각의 EULA가 있고, 대부분 재배포를 금지한다.
AI에 코드를 올리는 것이 재배포인지는 다툼의 여지가 있으므로, 안전한 쪽을 택한다.

### 대신 이렇게 한다

- 사용법 질문 → 공식 문서를 인용하거나 API 이름만 언급
- 오류 해결 → 에러 메시지와 자신의 호출 코드만
- 통합 방법 → 자신이 작성한 래퍼 코드만

---

## 3. 라이선스 관리

2027년 인디게임 출품전 제출을 대비해 아래를 `docs/licenses/`에 기록한다.

```markdown
| 에셋명 | 제작자 | 출처 | 라이선스 | 상업 이용 | 취득일 |
|---|---|---|---|---|---|
| Gaia for Unity 6 | Procedural Worlds | Unity Asset Store | Asset Store EULA | 가능 | 2026-08 |
```

### 특히 확인할 것

| 항목 | 왜 |
|---|---|
| Sketchfab 모델 | CC 라이선스 종류에 따라 상업 이용 불가한 것이 많다 |
| 무료 폰트 | 한글 폰트는 상업 이용 조건이 제각각이다 |
| 사운드 · 음원 | 국악 샘플은 출처 확인이 특히 필요하다 |
| AI 생성 에셋 | 사용한 도구의 상업 이용 약관을 확인한다 |

**"무료"와 "상업 이용 가능"은 다르다.** 반드시 라이선스 원문을 확인한다.

---

## 4. 코드에 남기면 안 되는 것

- 개인 계정 정보, 이메일
- API 키, 토큰
- 로컬 절대 경로 (`C:/Users/이름/...`)
- 테스트용 하드코딩된 IP 주소

`.gitignore`에 `.env`와 `*.local`이 있으므로 민감한 설정은 그쪽에 둔다.

---

## 5. 스크린샷 · 영상

발표나 이슈에 첨부할 때 확인한다.

- 다른 창의 내용이 보이는가
- 파일 경로에 실명이 있는가
- 알림 팝업이 찍혔는가

---

## 6. 유출을 발견하면

1. 추가 전송을 즉시 중단한다
2. 무엇이 · 언제 · 어디로 나갔는지 사실과 추정을 구분해 보고한다
3. 커밋 히스토리에 들어갔으면 팀장과 상의한다 (혼자 히스토리 재작성하지 않는다)
4. 키나 토큰이면 즉시 폐기하고 재발급한다
