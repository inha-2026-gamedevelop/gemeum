# 작업 브리프 템플릿

> 작업의 이유와 실행 계약을 함께 제공해 범위 이탈, 과잉 구현, 근거 없는 완료 주장을 줄인다.

---

## 사용 규칙

- 결과와 제약을 적고 세부 구현 순서는 실행자에게 맡긴다.
- 간단한 조회나 오타 수정에는 필요한 필드만 쓴다.
- 불명확한 값은 추측하지 말고 `{{미정}}`으로 표시한다.
- 분석만 요청할 때는 수정 금지를 명시한다.
- 검증 수준은 [검증 플레이북](03_VERIFICATION_PLAYBOOK.md)에 맞춰 정한다.

---

## 그믐 프로젝트 예시

```markdown
# 결계 단계별 축소와 범위 밖 피해 적용

## 배경
- 코어 루프의 시간 압박을 만드는 핵심 시스템. 이게 없으면 파밍 무한 반복이 된다
- 근거 문서: docs/02-game-design.md 2.1절, docs/03-technical-design.md 4.2절

## 산출물
- 최종 형태: BarrierController와 BarrierPhaseData ScriptableObject
- 이번에 포함: 반경 보간, 단계 전환, 범위 밖 피해, 10초 전 경고 이벤트
- 후속으로 미룸: 결계 시각 연출 (테크니컬 아트 담당)

## 영향 범위
- 담당 파트: AI · 보스 설계
- 수정할 씬: Dev_AI.unity
- 네트워크 영향: 서버 권위. 반경 값을 모든 클라이언트에 동기화
- 밸런스 데이터 영향: BarrierPhaseData 신규 생성
- 다른 파트와 충돌: 플레이어 HP 감소 경로가 전투 파트와 겹침 → 인터페이스 협의 필요

## 범위
- 읽기: Assets/01.Scripts/03.AI/, Assets/01.Scripts/02.Combat/Interfaces/IDamageable
- 수정 가능: Assets/01.Scripts/03.AI/Barrier/, Assets/09.Data/Barrier/
- 제외: Assets/01.Scripts/02.Combat/ (읽기만), Assets/00.Scenes/Main.unity

## 제약
- 반드시 지킬 것: 반경은 서버가 계산하고 클라이언트는 렌더링만
- 사전 승인 필요: 없음
- 스코프 잠금 위반: 해당 없음

## 완료 기준
- [ ] 4단계 반경이 각각 30초에 걸쳐 보간된다
- [ ] 범위 밖 플레이어에게 단계별 피해가 매 초 적용된다
- [ ] 축소 10초 전 경고 이벤트가 브로드캐스트된다
- [ ] 수치가 전부 ScriptableObject에 있다
- [ ] 검증 결과와 미검증 항목을 구분해 보고한다

## 검증
- 위험도: 높음 (공유 상태, 네트워크)
- 최소 수준: L1 + L2 + L3
- 멀티플레이 등급: M2
- 관찰할 성공 신호: 세 클라이언트의 미니맵 원 반경이 같고, 밖에 선 플레이어만 HP가 깎임
- 중단 조건: 클라이언트마다 반경이 다르면 즉시 중단하고 동기화 방식 재검토
```

## 분석 전용 변형

분석만 필요하면 아래 제약을 추가한다.

```text
읽기 전용으로 조사하라. 어떤 파일도 수정하지 마라.
원인, 선택지, 영향, 근거를 보고한 뒤 중지하라.
수정은 별도 승인된 작업으로 분리하라.
```

## 작성 전 점검

- 목적이 구현 절차가 아니라 관찰 가능한 결과로 적혔는가?
- 수정 가능 범위와 제외 범위가 겹치지 않는가?
- 완료 기준마다 확인 방법이 있는가?
- 네트워크 영향과 씬 소유권을 검토했는가?
- 스코프 잠금 항목을 건드리지 않는가?
