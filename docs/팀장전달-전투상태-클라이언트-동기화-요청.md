---

## 한 줄 요약

파티원 양도 안내(`[G]`)를 **전투 중에는 화면에서 숨기고 싶은데**, 지금 구조로는 순수 클라이언트가
전투 중인지 알 방법이 없습니다. `PlayerStatus`에 "마지막으로 전투한 시각"을 SyncVar로 하나
내보내 주시면 해결됩니다. 이 파일은 팀장님 소유 영역이라 제가 직접 고치지 않고 요청만 남깁니다.

---

## 왜 지금 보내는가

파티원 곁에 서면 상대 머리 위에 `양도 [G]` 안내가 뜨고, G를 누르면 배낭이 열려 장비를
끌어다 넘기는 기능을 만들고 있습니다. 화면과 요청 경로는 다 됐는데, **전투 중 처리만 막혀 있습니다.**

서버는 전투 중 양도를 거절합니다. 그런데 클라이언트가 그걸 몰라서 안내가 그대로 떠 있고,
누르면 창이 열리면서 마우스 커서가 풀리고 이동 입력이 잠깁니다. **전투 중에 이러면 죽습니다.**

---

## 증상

1. 잡귀와 싸우는 도중 파티원 옆을 지나간다.
2. 상대 머리 위에 `양도 [G]` 안내가 그대로 떠 있다.
3. G를 누르면 배낭 창이 열리고 커서가 풀린다. 그동안 움직일 수 없다.
4. 장비를 올리고 확인을 누르면 그제서야 "전투가 끝난 뒤 잠시 기다려 주세요."가 뜬다.

호스트(에디터에서 Play한 사람) 화면에서는 이 문제가 **안 보입니다.** 뒤에 설명하는 이유로
호스트만 전투 상태를 정확히 읽기 때문입니다. 참가자 화면에서만 재현됩니다.

---

## 재현 절차

1. 3인으로 접속해 필드 런을 시작한다 (호스트 1 + 참가자 2).
2. **참가자 화면**에서 잡귀를 때려 전투 상태로 만든다.
3. 맞은 직후 5초 안에 다른 파티원에게 3m 안으로 붙는다.
4. 상대 머리 위 안내가 떠 있는지 본다 → **떠 있으면 재현된 것이다.**
5. 호스트 화면에서 같은 행동을 하면 안내가 사라진다 → 두 화면이 다르게 동작한다.

---

## 원인

전투 여부의 원본은 `Assets/01.Scripts/00.Common/Utility/CombatClock.cs`입니다.

```csharp
public static class CombatClock
{
    private static readonly Dictionary<uint, double> _lastCombatByNetId = new Dictionary<uint, double>();

    public static void ServerNotifyDamage(uint victimNetId, uint attackerNetId, double gameplayTime) { ... }
    public static bool IsInCombat(uint netId, double gameplayTime, float outOfCombatSeconds) { ... }
}
```

이 딕셔너리는 `ServerNotifyDamage`로만 채워지고, 그 호출은 서버에서만 일어납니다.
호스트는 서버와 클라이언트가 같은 프로세스라 값이 채워져 있지만, **원격 클라이언트에서는 딕셔너리가
영원히 비어 있어** `IsInCombat`이 항상 `false`를 돌려줍니다. 그래서 참가자 화면만 잘못 동작합니다.

서버가 양도를 거절하는 자리는 `Assets/01.Scripts/04.Systems/Economy/TransactionServiceUtility.cs`의
`EvaluatePlayers`입니다. 여기서 보내는 쪽과 받는 쪽 **양쪽 모두** 전투 중이 아니어야 통과합니다.
유예 시간은 `CombatConfigSO._interactOutOfCombatSeconds`(현재 5초)입니다.

```csharp
double now = RunTimeLocator.Current.GameplayElapsedSeconds;
if (CombatClock.IsInCombat(first.netId, now, combat.InteractOutOfCombatSeconds) ||
    CombatClock.IsInCombat(second.netId, now, combat.InteractOutOfCombatSeconds))
{
    return TransactionRejection.InCombat;
}
```

클라이언트가 이 판정을 미리 하려면 **두 사람 모두의** 마지막 전투 시각을 알아야 합니다.
체력 SyncVar로 "맞은 것"은 유추할 수 있지만 "때리기만 하고 맞지는 않은" 경우를 놓칩니다.
그래서 유추로는 서버 판정과 어긋납니다.

## 제안

`Assets/01.Scripts/02.Combat/Player/PlayerStatus.cs`(팀장님 소유)에 SyncVar를 하나 더해 주시고,
`Net/` 쪽 계약에 올려 주시면 됩니다. 값은 이미 서버가 갖고 있는 것을 그대로 내보내는 것이라
새로 계산할 것은 없습니다.

```csharp
// 서버가 CombatClock에 기록하는 값을 그대로 내보낸다.
// 전투 중 상호작용 안내를 숨길지 판단할 때 세 화면이 같은 값을 보게 하려는 것이다
[SyncVar] private double _lastCombatGameplayTime = CombatClock.NEVER;

public double LastCombatGameplayTime => _lastCombatGameplayTime;
```

기록 지점은 이미 `CombatClock.ServerNotifyDamage`가 불리는 세 곳(플레이어·잡귀·보스의 `TakeDamage`)으로
모여 있으니, 거기서 해당 플레이어의 `_lastCombatGameplayTime`도 같이 갱신해 주시면 됩니다.

**판정을 클라이언트로 옮겨 달라는 요청이 아닙니다.** 판정은 지금처럼 서버가 계속 하고,
클라이언트는 "안내를 띄울지 말지"라는 표현에만 이 값을 씁니다. 권위 경계는 그대로입니다.

값을 받으면 제 쪽에서 이렇게 씁니다. 추가 작업은 제가 합니다.

```csharp
// 서버가 거절할 상황이면 안내를 아예 띄우지 않는다
double now   = RunTimeLocator.Current.GameplayElapsedSeconds;
float  grace = GameDB.Combat.InteractOutOfCombatSeconds;
bool inCombat = ((now - local.LastCombatGameplayTime)  < grace) ||
                ((now - target.LastCombatGameplayTime) < grace);
```

## 예상 비용

| 항목 | 규모 |
|---|---|
| `PlayerStatus` SyncVar 선언 + 프로퍼티 | 3줄 |
| 서버에서 기록 지점 연결 | `CombatClock.ServerNotifyDamage`가 불리는 곳 옆에 1~2줄 |
| 제 쪽 UI 반영 | 제가 합니다 |
| 검증 | 3인 접속. 참가자가 잡귀를 때린 직후 안내가 사라지는지 |

double 하나가 사람당 추가됩니다. 값이 바뀌는 빈도는 피해가 들어가는 빈도와 같습니다.
대역폭이 걸린다면 `float`(런 시작 기준 경과 초)나 "전투 중인가" `bool` 하나로 줄여도
제 쪽은 상관없습니다. 어느 형태든 알려 주시면 맞추겠습니다.

## 그때까지의 상태

지금은 안내가 전투 중에도 뜹니다. 대신 확인을 눌렀을 때 서버가 돌려준 사유를 그대로 보여 줍니다
("전투가 끝난 뒤 잠시 기다려 주세요."). 줍기·객주 안내도 같은 방식으로 동작하고 있어
당장 어긋나는 동작은 아니지만, 창이 열리면서 입력이 잠기는 점은 그대로 남아 있습니다.
